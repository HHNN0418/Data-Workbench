# 看板实施记录

## 1. 接口与页面结构

- 读取 `docs/CONTRACT.md`、`docs/PLAN.md`，按合同实现本地 HTTP 客户端。
- 创建 `web/index.html`、`web/app.js`、`web/style.css`；无框架、CDN、第三方浏览器依赖。
- 八页：概览、帖子、账号、本队积分、新闻、分析、运行状态、规则。
- 响应式左导航、中文界面、键盘可操作控件、加载/错误/重试/空数据状态、悉尼时间显示。

## 2. 数据查看与本地操作

- 概览显示真实记录数量、官方快照、对账状态、质量说明和采集趋势。
- 帖子支持关键词、作者、类型、归属筛选与分页；详情显示正文版本、互动曲线、原始快照、Feed 排名、回复/转发、标签及来源字段。
- 账号提供搜索、分页及本队 ID/归属证据登记；未知归属不判定为外队或 NPC。
- 官方积分支持 CSV 本地上传、总分快照登记、绝对/区间差额、赛道流水、未解析事件、导入批次和历史曲线。
- 新闻支持搜索、分页、全文展开与原始字段查看。
- 运行页支持限额配置、单次公开采集、状态自动刷新、调用日志、HTTP 状态、断点、在线备份下载。
- 提供帖子、账号、新闻、官方流水、API 日志和已保存分析的 CSV 导出。

## 3. 分析与规则

- 分析参数：观察窗口、容差、最大基线延迟、小时/日分组、作者、本队/未知、发布起止时间。
- 展示概要、时间序列及互动增量、账号分组、逐帖真实窗口增长、相关性及样本数、词频、帖子/账号引用关系、数据质量与排除原因。
- 支持保存分析参数和结果；完整字段保留可展开查看。
- 动态读取当前规则、核验来源、倍率、Red/Blue/Polling 条款及限制。
- 独立情景计算支持 Red、Blue 帖子、Blue 账号、正式民调、公投、基线民调六类模板，可编辑完整参数；缺少条件明确列出。
- 明确区分公开观测、官方记录、假设情景；热度不作积分、公开计数不作 NPC 计数、不作单帖官方分数归因。

## 4. 核验与边界

- `node --check web/app.js`：通过。
- 静态检查：无 `innerHTML`，外部正文/日志/规则均使用 `textContent`；SVG 由 DOM API 创建。
- 所有请求为本地同源地址；本地 POST 使用 bootstrap 返回的 `X-CTN-Token`。
- 空值、无效数值、无样本相关系数保持未知；趋势缺失点不连线，负变化保留。
- 分析结构已按 `analytics.py` 实际返回字段适配；积分结构按 `scoring.py` 实际返回字段适配。
- 未启动服务、未发送比赛消息、未修改远程平台数据、未发布网页。
- 浏览器视觉与真实 API 联调由主 agent 集成验收；本报告不将静态检查写成浏览器通过。
- 数据量较大时，浏览器表格采用接口分页；分析数组默认展示最多 100 行，其余保留完整字段/导出入口。数据库分析计算能力由后端决定。
- 时间输入控件按浏览器本地时区解释，再转 UTC；界面显示统一使用 `Australia/Sydney`。

# Agent 关注度竞赛：独立规则核验与验收清单

核验日期：2026-10-20，Australia/Sydney。此文件是独立验收依据，不表示以下功能已经实现或启用。

## 官方规则核验

已读取 [CTN 2026 官方 Scoring，第 1、5、6 节](https://capturethenarrative.com/info/competitions/2026/scoring/)。页面标注 2026-10-20 更新，本次更新涉及 Blue 举报裁决等待时间；关注度计分未因此改变。

| 规则 | 当前官方规定 | 本地结论 |
| --- | --- | --- |
| 互动权重 | 浏览 1、点赞 5、转发 10、回复 15、被关注 20、被取消关注 -20 | `scoring.ENGAGEMENT` 一致，可精确复用常数 |
| 计数资格 | NPC 行为；按帖子、公民、公民会话去重 | 当前公开快照不提供完整身份和会话，不能精确复现 |
| 浏览上限 | 每队每悉尼自然日最多 500 次获分浏览，先封顶后乘倍率 | 可实现同规则的内部日账；不能据此声称知道官方余额 |
| Red 倍率 | Day 0–6 为 1，Day 7–12 为 2，Day 13 起为 4；正负同乘 | `rules_context()` 的日历和倍率一致 |
| 倍率时点 | 官方记录分数时生效；NPC 通常结束会话后批次入账 | 快照时间不等于入账时间，内部必须明确使用观测时点代理 |
| 撤赞 | 不产生扣分 | 不能对点赞负差直接计负分 |
| 转发链 | 收益属于原帖团队 | 无法核实原帖归属时不能给中间转发角色获奖 |

本竞赛只选用关注度部分。观点变化、贡献、举报和民调不纳入此次角色排名；“官方权重一致”不等于“覆盖全部官方得分”。

## 已有数据能做什么

- `ctn_data/scoring.py` 保留官方权重、悉尼日历、倍率和参考链接；其 `calculate_scenario()` 明确拒绝把公开计数当作官方 NPC 事件。竞赛估分应另建读模型，不能取消这项隔离。
- `ctn_data/ingest.py:save_counters()` 保存四项非负整数或 `NULL`，并保留原始来源。同一帖子、同一观测时间的冲突进入 `counter_conflicts`，不会静默覆盖。
- `posts` 有作者、回复父帖和转发原帖字段；可以在原帖已采集且归属明确时检查对应关系。
- `agent_feedback` 有账号与已确认本地动作的精确关联，可作为归属核验的输入。它的汇总只覆盖最近 20 篇本人帖，动作又受本地保留窗口限制，不能直接作为小时竞赛账本。

## 当前缺口与实施限制

1. **采样精度不同。** `collector._counter_windows()` 沿用分析模块的基线不晚于发布后 10 分钟、60 分钟端点容差 ±12 分钟。设计要求基线不晚于 2 分钟、端点在目标后 0–2 分钟，必须使用独立条件；不能因已有分析窗口“满足”而把竞赛视为完整。
2. **缺少独立入库时间。** `counter_snapshots` 和对应原始记录目前主要记录 `observed_at`。若需要区分“及时采到、稍后导入”和“实际迟采”，应补充可信 `ingested_at` 或等价持久日志，不能用自增 ID 猜测时间。
3. **缺少 NPC 会话事件。** 没有完整入站 follow/unfollow 事件、NPC 会话去重键及官方入账时间。出站关注回执、粉丝净变化、全队官方总分变化都不能替代它们。首版四项指标全员统一；关注项显示未接入。
4. **缺少完整持久归属。** 当前已完成草稿最多保留 500 条。竞技归属必须在确认发布时持久化，不能依赖未来仍能找到原草稿，也不能在换绑账号时搬运旧成绩。
5. **本队互动排除证据不足。** 本地“对目标点过赞”不能证明动作已进入某个观测差值。不能机械减去出站操作数，也不能把未知身份当作已证明是 NPC。
6. **覆盖不完整。** 全队浏览池需要已识别本队账号所有被跟踪帖子，包括人工、历史和无 Agent 归属内容；中途上线和未采集内容必须显示覆盖限制。只对参赛帖各算一个 500 池是错误实现。

## 核心算法验收向量

所有测试使用隔离数据库、固定时钟、模拟平台/模型。以下期望同时适用于重放，不使用真实发布验证调度。

| 编号 | 输入与操作 | 必须得到的结果 |
| --- | --- | --- |
| S01 高水位 | 点赞 `10→13→9→13→15` | 首个快照只作基线；新增共 5，基础分 25；下降和恢复到旧峰值不重复得分 |
| S02 端点回退 | 基线 10，中间 13，合资格端点 9 | 保留异常证据，暂不参与资源奖励；不能把 9 当正常完整端点 |
| S03 缺字段 | 四项中一个字段为 `NULL`，其余有数据 | `score=null`；可显示已知分项小计，但不能将小计混入完整排名；缺失不是有效 0 |
| S04 浏览池 | 全队当天已计 490，同真实批次 A/B 新增 12/8 浏览 | 余下 10 按 6/4 分配；人工本队帖也占池；再次查询或结算不能重复消耗 |
| S05 日边界 | 同一帖子午夜前后两快照，累计浏览仍增长 | 高水位不重置；新增量按后次观测归内部悉尼日，标注跨日；不按时间猜拆 |
| S06 倍率边界 | 悉尼 2026-10-25 23:59:59 / 10-26 00:00:00；10-31 23:59:59 / 11-01 00:00:00 | Red 分别 1/2、2/4；500 个获分浏览在 ×4 阶段为 2000 分 |
| S07 时间窗口 | 发布后 2 分钟内真实基线；端点分别在基线后 59:59、60:00、62:00、62:01 | 仅 60:00 至 62:00 合资格，选择窗口内首个有效端点；晚采不能回填目标值 |
| S08 缺基线 | 确认发布后始终没有合资格早期基线 | 候选仍进入到期分母，状态不可评；不能因为未建基线而从覆盖率消失 |
| S09 覆盖阈值 | 5 个到期候选中完整 4 个 / 3 个 | 80% 可汇总完整样本并显示 1 个排除；60% 本轮未知，不补零；成熟角色冻结调整 |
| S10 归属 | 人工帖、历史帖、点赞对象、另一个作者的转发原帖、账号换绑旧帖 | 不错误计给当前角色；浏览账与竞技归属分开；重复回执仅一次 |
| S11 定时结算 | 11:04 基线，12:04 目标，12:05 端点 | 归 UTC 对应的 12–13 时轮；13:10 前不封存；实际采样长度 61 分钟 |
| S12 迟到与修订 | 同一旧轮导入迟到有效快照，再重复导入/重算 | 只修订原轮有效版本，不变成新轮、不重复发奖励；已执行操作不撤回 |
| S13 纠错传播 | 三天前错误峰值被撤销，近期仍依赖旧高水位 | 从受影响检查点重放到现在；48 小时奖励修订范围不能截断高水位纠错 |
| S14 同时刻冲突 | 同帖同观测时间出现两个不同计数 | 保留冲突，不按输入顺序随机替换；结果需要明确排除/解决策略 |

## 资源与模型验收

- `N=0` 无分配；`N=1` 可使用全部机会，但不触发竞争性模型晋级。
- 全零、全负、全员同分、不足两名可比者：没有赢家，竞技池均分；不能按总分相除。
- 并列使用平均名次；正分榜前列与后列必须按同一规则决定，不得用 ID 拆散并列奖励。
- 四角色份额 `30/30/25/15`，前三得分 `360/240/120`、第四保护中：原始目标 `30/23.33/16.67/30`；统一约束投影后为 `28/24/20/28`，合计 100%。
- 成熟成员稳定时每轮相对变化不超过 ±20%，每人目标上限 `min(1,2/N)`；不先逐个截断再普通归一化。新成员加入需先重建基准并记录原因。
- 第一次满足真正自动运行就绪时写入保护起点；重启、暂停、改名、清忆、模型变更和同账号删除重建不重新领取。保护到期但样本不足仍显示观察中。
- 连续两轮领先才能升档；同一轮 revision 不能充当第二轮。数据不足/故障保持层级并清零连续计数。
- 增强模型比例是后续调用目标，须冻结每个任务实际模型与预算；连接失败或预算不足的回退不能当作竞争降档。
- 所有自动生成和发布路径通过同一份仲裁，包括“生成后立即发布”。人工操作、暂停、待审和不确定结果不能被竞赛绕过。
- 关闭竞赛立即恢复共享调度；保留已运行任务、现有冷却、预算及历史，不能为提速重发未确认请求。

## 集成发布门槛

1. GET 竞赛/反馈页面只读，不偷偷结算、发起模型调用或发布。
2. 配置写入有鉴权、CSRF 和版本校验；预览无副作用，保存仅作用未来轮次。
3. 多线程/多进程同时结算及重启恢复不能重复创建有效分配。SQLite 和 PostgreSQL 使用同一业务断言。
4. 删除旧草稿、清理 UI 缓存、恢复备份后，归属与新人保护账仍然存在。
5. UI 明确区分待成熟、不可评、有效零分、保护中和无产出；内部估算与官方分账分开展示。
6. 没有证据支持 60–62 分钟同龄窗口时，允许先交付可见的只观察结果；不能把宽容差分析结果包装为已经通过资源竞赛验收。

独立复核建议：先确定计分、归属、结算、分配的纯函数或窄接口，再由另一组集成测试调用这些公开接口构造上述数据。不要用复制实现公式的测试替代端到端期望值。

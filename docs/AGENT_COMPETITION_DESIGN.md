# 内容研究与 Agent 关注度竞赛设计

设计版本：v0.1。日期：2026-10-20，Australia/Sydney。

本设计把现有热门帖分析、角色表现反馈和共享额度调度连接起来：内容研究 Agent 提出有证据的写作建议，发文 Agent 自主采用，系统以官方互动权重计算内部关注度成绩，每小时调整下一轮资源。此文件规定拟实现的行为；当前运行系统尚未开启这些功能。

## 1. 产品决定

| 项目 | v1 决定 |
| --- | --- |
| 研究入口 | 数据分析 → 内容研究，与已有 AI 分析并列 |
| 竞赛入口 | Agent → 竞赛与资源，保留现有额度管理 |
| 计分目标 | 官方互动计分中的关注度部分，不添加 AI 主观质量分 |
| 数据口径 | 公开观测估分，与官方实得账本分开 |
| 研究周期 | 每 15 分钟检查新样本；有足够新证据才调用模型 |
| 单帖观察 | 早期真实基线之后约 60 分钟，显示实际观测长度 |
| 竞赛周期 | 每小时结算；预留采样与数据到达宽限 |
| 默认资源池 | 40% 基础、40% 竞技、20% 探索 |
| 新人保护 | 首次自动运行就绪起 60 分钟，持久化且不重复领取 |
| 模型奖励 | 连续两轮领先后提高增强模型调用比例 |
| 初次部署 | 默认关闭；先观察计分，再逐步启用调度和模型奖励 |

“资源比例”是有需求时获得机会的调度权重，不是强制发帖任务。读资料、通知处理、结果核对不因比赛落后而失去基本服务。研究 Agent 不参与发文竞赛，也不使用角色账号。

## 2. 现有基础和新增职责

| 现有模块 | 可复用能力 | 本设计需要补充 |
| --- | --- | --- |
| `ctn_data/ai_evidence.py` | 热门与普通对照、作者分散、证据与特征提取 | 同龄成熟窗口、结构化研究结果 |
| `ctn_data/ai_research_context.py` | 统计、快照、回复关系 | 采用策略后的表现与反例 |
| `ctn_data/agent_feedback.py` | 本人帖子反馈、来源与采样时间 | 独立竞赛读模型，不能直接用最近 20 帖的累计数排名 |

| `ctn_data/analytics.py` | 真实基线和端点配对 | 竞赛专用端点规则，不直接沿用分析默认宽容差 |
| `ctn_data/agent_budget.py` | 共享额度、冷却、租约、使用统计 | 在官方总额度内部安排各 Agent 的使用机会 |
| `ctn_data/agent_generation.py` | 后台任务、取消、结果保存 | 启动任务时冻结实际模型和分配版本 |
| `ctn_data/scoring.py` | 官方权重与悉尼比赛日历 | 只读取规则，另建估分账本 |

建议新增 `agent_research.py`、`agent_strategy.py`、`agent_competition.py`、`agent_allocation.py`，分别负责研究、建议分发、估分结算和资源调度。数据库和 API 继续使用现有后端。

职责顺序：

1. 采集器保存公开资料和真实计数快照。
2. 研究 Agent 读取热门、普通对照和本队策略效果，生成策略简报。
3. 发文 Agent 在正常决策中读取相关简报，自主决定采用、调整或跳过。
4. 已确认发布回执建立 Agent 与帖子、策略、实际模型的归属。
5. 估分器读取观测，不调用模型，计算分项和完整度。
6. 结算器冻结每轮成绩；分配器计算下一小时的机会比例和模型比例。

LLM 负责解释与建议；资格、计分、预算、资源份额和实际执行由程序决定。

## 3. 计分合同

### 3.1 官方规则与内部估算

规则来源为 [CTN 2026 Scoring 第 1、5 节](https://capturethenarrative.com/info/competitions/2026/scoring/)，本设计使用本次会话于 2026-10-20 核验的内容。

| 收到的行为 | 基础分 | v1 数据状态 |
| --- | ---: | --- |
| 浏览 | 1 | 公开计数的新高增量，并受全队内部日上限约束 |
| 点赞 | 5 | 公开计数的新高增量 |
| 转发 | 10 | 归属核实后的公开计数新高增量 |
| 回复 | 15 | 公开计数的新高增量 |
| 被关注 | 20 | 未具备同口径事件数据，全员统一不纳入 |
| 被取消关注 | -20 | 未具备同口径事件数据，全员统一不纳入 |

官方 Red 倍率为比赛 Day 0–6 ×1、Day 7–12 ×2、Day 13 起 ×4；正负分同乘。官方浏览每天每队最多计 500 次，悉尼午夜重置。取消点赞无扣分，转发链归原帖。

官方以 NPC、帖子和 NPC 会话去重，并以官方入账时间确定倍率。公开快照缺少 NPC 身份、会话和准确入账时点，因此 v1 使用明确标记的内部代理：

- 使用官方权重、日历和浏览上限。
- 按实际观测时间归内部计分日及倍率，不推断真实互动发生时间。
- 无法还原的项标为“未接入”，不伪造事件，不称为官方实得。
- 默认所有参赛者使用相同的四项指标集合；新增关注项必须整体升级规则版本，不能只给少数账号加分。
- `follow/unfollow` 出站操作不是“被关注／被取消关注”；粉丝净变化不能还原两个事件数。
- 估分结果不写入 `score_snapshots` 或官方活动流水，也不修改 `calculate_scenario()` 对公开计数的限制。

每一轮保存 `rule_version`、`estimator_version`、`metric_set` 和 `data_revision`，不同口径不混排。

### 3.2 累计计数的增量

对每个帖子、每种指标按实际观测时间排序，建立跨小时和跨日保留的高水位：

```text
第一份有效快照：作为基线，不假设此前为零，不获得增量。
H = 此前所有有效快照的最高值
本次观测新增量 = max(0, 当前计数 - H)
新 H = max(H, 当前计数)
```

例如点赞 `10 → 13 → 9 → 13 → 15`，新增量为 `0、3、0、0、2`，共 5 次，对应基础估分 25。下降后恢复到旧高水位不会重复得分，下降本身不生成扣分。

这个算法衡量“新观测到的峰值增长”，会漏掉期间取消后重新产生的互动；它不是官方事件还原。缺字段保持未知；计数下降标为异常。结算端点仍低于此前高水位时，该帖子暂不用于资源奖励，明细保留供检查。确认某快照错误后标记其被替代并重算，不永久保留错误峰值。

四项均具备可用数据时，单帖关注度估分为各条合资格增量的：

```text
sum(观测时点倍率 × (获分浏览 × 1 + 点赞增长 × 5 + 转发增长 × 10 + 回复增长 × 15))
```

缺任一启用指标时，`score=null`，另存 `known_component_subtotal` 供查看。不能拿部分分项小计和别人的完整成绩竞争。禁用的关注项与已启用但缺失的指标分别表示。

### 3.3 浏览 500 上限

建立一份全队内部观测日账。覆盖所有已识别本队账号的已跟踪帖子，包括历史帖、人工帖及不能归属某个 Agent 的帖子。新增浏览先在此账中分配额度，再由帖子评估引用分配结果。

- 高水位不在午夜重置，只有每天的已计浏览数重置。
- 第一次跟踪老帖只建基线，不把累计历史浏览挤进今天的额度。
- 先按每条观测的悉尼日期及规则版本分组，再按批次观测时间顺序消耗浏览额度。同一真实采集批次在同一日内使用比例分配和最大余数法，稳定排序解决余数并列。跨午夜的批次先拆日，两日不能共享剩余量或倍率。
- 例如已分配 490 次，同一批次 A 新增 12、B 新增 8，剩余 10 次分配为 A 6、B 4。
- 原帖明确属于另一个 Agent 时，转发链收益不能再次记给中间转发者。无独立本人计数对象的转发回执不产生本人的帖子成绩。
- 非竞赛帖消耗的观测额度记为“其他本队内容”，不分摊给参赛者。
- 同一增量只消耗一次日额度；重新查看或结算帖子不再次扣额度。

采集范围不完整或首次启用发生在日中，日账标注覆盖范围和启用时间。页面称“内部计分浏览已用”，不能显示为“官方剩余额度”。

跨午夜的增量全部按后一次实际观测时刻归日，标记 `crosses_day_boundary`，不按时间比例猜拆。倍率与浏览日账使用相同归日口径。

### 3.4 归属与队内互动

发布归属使用不可变链路：

```text
draft_id → confirmed post_id → agent_id + account_id + binding_epoch
        → strategy_version + actual_model_id + allocation_epoch + origin
```

只给精确归属的自动发布成果计 Agent 成绩。人工帖、历史未归属帖、点赞目标的热度不能计入该 Agent。一个账号同一时刻只能有一个参赛控制者。换绑账号开启新归属段，不搬运旧成绩；暂停、删除、清记忆保留历史记录。

已核实属于本队的入站互动应排除，但必须能证明其已包含在相应公开计数中，并以稳定标识去重。只有本地动作回执、无法确认是否进入计数时，标记该指标窗口受污染并暂不排名，不能机械地从计数差中减去操作次数。未知身份保留未知，浏览不能声称已经完全排除队内访问。

后续实施应先接入可核实排除的数据源，再启用竞技资源。不能把“无法证明来自本队”等同于“已证明来自 NPC”。

## 4. 帖子观察与小时结算

### 4.1 单帖时间轴

默认参数是工程起点，不是官方规定：

| 参数 | 默认 |
| --- | --- |
| 早期基线截止 | 已确认发布时间后 2 分钟 |
| 目标观测长度 | 真实基线之后 60 分钟 |
| 合资格端点 | 目标时点到目标时点后 2 分钟之间的第一份有效快照 |
| 实际观察长度 | 60–62 分钟，逐帖展示 |
| 结算宽限 | 每小时结束后 10 分钟 |
| 自动修订范围 | 最近 48 小时 |

发布后立即安排基线采样，接近目标时点安排到期采样。全部采样共用现有全队采集预算；不能为了保证榜单绕过限流。

没有早期真实基线、没有合资格端点、字段缺失或异常未解决时，该帖为“不可评／待核对”。第 65 分钟的新快照不能反推第 60 分钟的数值。实际在允许时段采到、只是稍后导入的快照可以作为迟到证据。

观察窗口是 `(baseline_at, endpoint_at]`。基础快照中的已有互动不计入该窗口，保留 `baseline_delay_seconds` 供解释。结算轮次由 `target_at = baseline_at + 60min` 决定，与端点晚了多少、数据何时导入无关。

确认发布时即登记评估候选和 `baseline_deadline = published_at + 2min`，不能等采到基线后才登记。有基线后按真实目标归轮；没有基线的帖子按 `baseline_deadline + 60min` 归入失败样本分母，避免最严重的漏采从覆盖率中消失。迟到的早期真实基线如果改变所属小时，原轮与正确轮一起修订，候选在当前有效版本中只出现一次。

### 4.2 每小时轮次

每轮覆盖目标成熟时刻落在一个小时内的帖子，UTC 保存边界，悉尼时间显示。例如：

```text
11:03 确认发布
11:04 取得基线
12:04 到达目标；12:05 取得端点，实际观察 61 分钟
归入目标时间为 12:00–13:00 的轮次
13:10 结算该轮；下一份资源分配有效至 14:10
```

夏令时重复的本地小时用 UTC 边界区分，不能只用本地 `YYYY-MM-DD HH` 作为唯一键。帖子只能归入一个轮次。

轮次状态：

```text
collecting → grace → sealed
                      ↳ revised（新增修订版本，旧版本仍可查）
```

每轮总分是该 Agent 合资格帖子分数之和，页面明确称“合资格样本总分”，不是所有已发帖子的完整成绩。榜单同时列出单帖平均分、原帖／回复／转发分项及合格／排除样本数，帮助解释成绩来源；这些解释指标不改变官方权重。

### 4.3 资格与数据不足

默认参赛条件：保护期结束、近 6 小时至少 3 个合资格成熟样本、本轮至少 1 个完整样本、本轮到期样本覆盖率至少 80%。覆盖率为完整可评样本数除以全部到期候选数，缺基线与异常候选也在分母。达到 80% 后只汇总完整样本，缺失样本不补零；因此必须显示排除数量。低于 80% 才使整个 Agent 本轮不可评。达到最低数量不代表已经有统计显著性。

| 状态 | 榜单与资源行为 |
| --- | --- |
| 首小时保护中 | 展示观察结果，不参加升降；基础＋优先探索 |
| 保护结束但不足 3 个近期成熟样本 | 观察中，基础＋探索；不按零分降模型 |
| 正常参赛，真实互动增长为零 | 有效 0 分，可参与排名 |
| 自主未发布、没有到期成果 | 显示“本轮无产出”，无竞技奖励；不记为采集失败 |
| 已发帖但覆盖不足 80% | 个人本轮分数未知，无竞技排名；已成熟角色冻结份额和模型，清零升降连续计数 |
| 系统采集或估分整体异常 | 冻结整个资源调整轮，沿用上轮份额和模型 |
| 暂停／待核对账号 | 不领取新增自动发布机会，仍可核对历史结果 |

连续 6 小时没有可用样本时发运行告警，不自动扩展采集配额，不因缺失数据编造成绩。

### 4.4 迟到与纠错

原始记录保留 `observed_at` 与 `ingested_at`，重复输入以来源和快照标识幂等处理。迟到或纠错要先重放受影响帖的高水位，再重算受影响日期的全队浏览分配，最后修订受影响轮次。

已经执行的发布和模型调用不追溯撤销。历史分配保存当时看到的分数版本。48 小时按被修订轮次的结束时间计算，限定自动重算历史排名和连续领先记录的范围，不截断高水位状态的依赖传播。

任何已确认的原始纠错，都必须从受影响快照之前的有效检查点重放到当前，重算受影响日期的全队浏览池，使现在和未来使用正确的高水位。较旧轮次的审计展示也随数据修订，但不自动补发旧奖励；不能因为错误峰值在三天前，就继续压低今天的增长。重算期间相关结果标为处理中并冻结资源变化，不能读到半套日账。

修订仅替换原 `round_id` 的有效成绩版本，不算一个新轮次，也不把旧轮差额加到当前轮。每个决策边界只使用该轮及相邻上一轮的最新可用版本判断连续表现，最多变化一个模型层级；同一轮多个 revision 不能构成连续领先或重复发奖。规则版本升级不会把旧结果悄悄换成新口径。

## 5. 内容研究和策略采用

### 5.1 研究任务

每 15 分钟检查一次，默认研究最近 6 小时，必要时补充至 24 小时。有至少 10 条新增成熟样本，且热门和普通对照各至少 5 条时生成新版本；不足时说明样本不足，沿用未过期简报。简报默认有效 2 小时。

优先用同类型、相近发布时段与观测年龄的对照，并分散作者；本队策略评估只使用已记录采用关系的成果。全平台研究按可见互动特征选样，不能给未知归属账号套用本队 500 浏览日账。

统计由程序计算；模型输出可检验的假设、适用场景、反例和证据。不能把相关性表述成已证明的因果关系。

### 5.2 简报字段

```text
brief_id, version, generated_at, expires_at
scope, source_cutoff, sample_counts, coverage, model_id, input_hash
strategies[]:
  strategy_id
  hypothesis
  applicable_topics, applicable_actions
  suggested_change
  supporting_source_ids, counterexample_source_ids
  sample_n, uncertainty, status = hypothesis | testing | retained | retired
```

来源引用必须属于实际送入模型的证据集合。输出不合格不激活新版本，保留上一个仍有效版本；过期后显示无可用建议，不把失败摘要传给发文 Agent。

### 5.3 发文上下文和采用记录

在现有 `performance_feedback` 旁增加 `strategy_context`，每次最多 3 条相关建议及其反例；按角色兴趣、当前来源和允许动作筛选。建议与身份记忆分开，不覆盖人设。

决策响应增加：

```text
strategy_decision:
  brief_id, strategy_id, version
  disposition = adopted | adapted | skipped
  changed_variable
  reason
  proposed_next_experiment
```

服务端验证所选版本确实在此次上下文中；未使用可留空。下一轮建议更换不改变已经生成的草稿。每篇优先试一个主要表达变量，便于解释结果。

简报更新本身不强制所有角色发帖；在下一个正常决策中读取。角色可以跳过建议，保留自身语气。策略效果页同时展示模型版本、动作类型与额度变化，避免把增强模型的效果全部归给写作策略。

## 6. 资源分配和模型奖励

### 6.1 两类调度机会

生成机会和自动发布机会分别排队，使用同一份目标份额，但独立记账。发帖、回复、转发共用发布池，仍服从现有平台路由限额。

所有自动路径必须经过同一个仲裁入口，包括“生成完成后立即发布”；不能只在轮询 `tick()` 中加权。人工操作沿用原有执行流程，占用实际共享额度但不领取竞技奖励，也不算角色自主成绩。

调度使用持久化的加权公平队列。只在有新资料或有效待执行动作时申请机会，空闲 Agent 不囤积无限额度。失败请求保留实际预算消耗与服务端冷却，不靠重试获得额外优先权；结果不确定继续沿用核对机制。

### 6.2 目标份额

设 `N` 为当前自动运行就绪、允许至少一种发布动作且没有账号阻塞的 Agent 数。`N=0` 时不创建分配；`N=1` 时该角色可获得全部可用机会，但没有竞争性模型升档：

```text
target_i = 0.40 × base_i + 0.40 × competition_i + 0.20 × exploration_i
base_i = 1 / N
```

竞技池按合资格榜单分配。排序依据仅为固定官方权重的内部总成绩；不添加文风、人设或模型自评分。单帖平均分与单位模型费用产出用于解释及实验评估，不暗中替代用户指定的总成绩。

设 `G` 为合资格 Agent 集合，`m = len(G)`，`r_i` 为成绩从低到高的平均名次（最低 1，最高 m）：

```text
当 m >= 2、存在正分且并非全员同分：
  w_i = 0.5 + (r_i - 1) / (m - 1)，i 属于 G
  competition_i = w_i / sum(w_j)，其他角色为 0
否则：
  competition_i = 1 / N
```

并列用平均名次取得相同权重；只有调度先后可以用稳定 ID 排序。负分保留原值，并在有正分的有效赛局中正常排序；全员不为正、完全同分或不足两名可比者时，没有赢家，竞技池回流均分。不使用分数直接相除，避免负数和零分导致异常。

探索池优先保护中及尚未取得参赛资格的角色，集合内均分。额外的新手探索优先资格默认最多延续首次就绪后的 6 小时；到期仍不足样本者保留基础机会并参与普通轮转实验。没有优先对象时，分配给已登记的小规模策略对照；没有实验需求则均分。探索选择由系统规则决定，不能只靠 Agent 自报“我需要实验”获得资源。

目标份额合计 100%。上限为 `min(1, 2/N)`。稳定成员集合中，保护期结束者下一轮份额在上轮的 80%–120% 内调整。已取得参赛资格但本轮因数据故障不可评者暂时固定在上轮份额，而不是用未知分判负。

统一投影到可行份额，不能先分别截断、再简单归一化：

```text
baseline = 上轮实际目标份额
lower_i = 0.40 / N
upper_i = min(1, 2 / N)
保护结束者：
  lower_i = max(lower_i, 0.80 × baseline_i)
  upper_i = min(upper_i, 1.20 × baseline_i)
已成熟但本轮数据故障者：
  lower_i = upper_i = baseline_i
求 lambda，使 sum(clip(target_i + lambda, lower_i, upper_i)) = 1
share_i = clip(target_i + lambda, lower_i, upper_i)
```

`lambda` 可以二分求解，内部使用未四舍五入的值；显示百分比用最大余数法保证合计 100%。保护期保证基础和探索资格，没有额外承诺每个新人至少占全队 `1/N`。

新增／退出时先重建基准：新角色初始 `1/N`，剩余份额按继续运行角色的旧份额比例分配，再投影到基础下限和 `2/N` 上限；没有旧成员则均分。相对新基准应用平滑，并记录 `membership_rebase`。稳定成员之间正常调整、因成员变化重新定基准两种原因分别展示。

例如四个角色，当前份额为 `30%、30%、25%、15%`，前三人成绩为 `360、240、120`，第四人保护中：原始目标为 `30%、23.33%、16.67%、30%`；应用前三人平滑下限后，最终为 `28%、24%、20%、28%`。第一名仍获得成熟角色中最多的资源，但新人加入时不保证赢家相对上轮一定增长。资源奖励是全队总池内的相对倾斜。

空闲份额可借用。`2/N` 限制目标保障份额，不限制借用后的实际使用率；否则只有一个角色有需求时会浪费资源。借用单独展示，不形成未来固定权利，借用产生的帖子照常计分。

### 6.3 模型池

模型仅来自已配置并允许用于该用途的连接。配置“标准模型”和“增强模型”；增强是经实际评测选择的角色，不按价格直接判断质量。

| 层级 | 增强模型目标比例 | 升降条件 |
| --- | ---: | --- |
| 标准 | 0% | 新人和默认状态 |
| 奖励 | 50% | 连续两轮进入合资格正分榜前 1/3 |
| 加强 | 80% | 已在奖励层，再连续两轮满足领先条件 |

至少两名可比较的合资格 Agent 时才推进竞争升档。按降序平均名次计算，前列为 `rank <= ceil(m/3)`，后列为 `rank > m-ceil(m/3)`；并列同等待遇，全员同分不升降。升档还要求成绩为正；连续两轮处于后列且落后于前列时降一档。数据不足和系统故障保持层级，但清零连续计数，避免把隔了很久的两轮拼成连续领先。增强预算不够时按份额公平分配。

每个任务启动时固定实际模型、模型池版本、预留 token／费用预算和分配版本。按调用序列的累计目标差额选择标准或增强模型，避免靠随机数造成短时配比失控。只影响后续任务，不直接修改角色的 `provider_id`、人设版本或待审草稿资格。模型失败沿用既有失败处理；确认请求未执行或原任务已结束后，下一任务可回标准模型，禁止不确定时并发重发。预算或连接导致的回退不是竞技降档，应单独显示原因。

研究调用使用单独的小预算，避免挤占角色基本服务。全队设置生成请求、token 和可选金额上限；使用金额上限时，未配置可靠单价的模型不进入自动增强池。费用为预留上限与实际回执核销，不把“调用次数份额”等同于费用份额。

## 7. 新人保护

首次满足已绑定账号、可用模型、角色启用、自动模式、队伍持续运行开启时，写入一次 `first_ready_at` 与 `protected_until = first_ready_at + 60min`。资料创建时间不是上线时间。

保护期间计时不因暂停或重启重置。清记忆、改名、改模型不重置；同一账号已领取的保护记录在删除重建后仍有效。账号更换开启新归属段，是否具有保护资格由账号此前是否领取决定；可参赛身份只能由用户创建和启用，Agent 不能自行新增账号或复制身份领取探索资源。

保护结束只表示可以获得参赛资格，不把未成熟样本立即判为失败。样本不足继续保持基础及受限探索机会。保护不覆盖账号错误、执行结果不确定和平台限流。

## 8. 持久化数据与接口

### 8.1 新增数据

现有完成草稿只保留有限条数，请求统计只有短时间窗口；不能据此重建完整小时竞赛历史。

| 表／记录 | 关键内容与约束 |
| --- | --- |
| `agent_competition_profiles` | 稳定参赛身份、账号归属段、首次就绪与保护记录；同账号不能双重参赛 |
| `agent_publication_attributions` | 草稿与帖子一对一归属、人工／自动、策略及实际模型；确认发布时写入 |
| `agent_research_briefs` | 研究范围、证据、简报版本、有效期、调用预算与状态 |
| `agent_strategy_decisions` | 每次决策采用、调整、跳过及对应草稿；不能由模型写入表现分 |
| `agent_attention_observations` | 不可变观测、来源标识、数值、实际采样和入库时间、修订关系 |
| `agent_attention_ledger` | 高水位增量、内部计分日、浏览分配、倍率、分项、排除原因 |
| `agent_competition_rounds` | UTC 边界、口径、截止、状态、修订版本，轮次与版本唯一 |
| `agent_competition_results` | 每人分数、样本、覆盖、资格、快照依据，与轮次关联 |
| `agent_resource_allocations` | 当前／下一轮份额、约束裁剪、模型层级、预算、依据的分数版本 |

浏览日上限可作为账本的按日物化汇总，必须在事务／日级锁下统一分配，不给每个 Agent 建一个独立 500 池。重算计算完成后原子切换到新派生版本，页面不读取半轮结果。

原始观测、派生账本和实际分配决定分别保留。账户凭据、API Key 和模型私密推理不进入这些表。全部新表接入 PostgreSQL／SQLite 结构、备份和迁移清单。

### 8.2 拟新增 API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/analysis/research` | 当前简报、样本、有效期、研究状态 |
| `POST /api/analysis/research/run` | 主动研究一次，受研究预算约束，返回后台任务 |
| `GET /api/analysis/research/{brief_id}` | 版本、证据与反例 |
| `GET /api/agents/competition` | 运行模式、当前轮、榜单、下轮分配 |
| `GET /api/agents/competition/rounds/{round_id}` | 结算版本与每项依据 |
| `GET /api/agents/{id}/performance` | 单角色窗口成绩、策略采用和模型记录 |
| `POST /api/agents/competition/preview` | 按已有数据预演配置，不改分配、不发起模型调用 |
| `POST /api/agents/competition/settings` | 带配置版本校验保存；只对未来轮次生效 |
| `POST /api/agents/competition/recompute` | 指定范围幂等重算内部账，不执行平台写操作 |

所有写接口沿用成员登录、CSRF 和审计；配置使用 `expected_version` 防止并发覆盖，耗时任务返回任务 ID。响应统一区分 `score`、`known_component_subtotal`、`eligibility`、`exclusions`、`observed_at` 与 `generated_at`。

## 9. 页面交互

### 9.1 数据分析中的内容研究

页面上方显示研究是否启用、数据截止时刻、模型和下一次检查时间。主体按策略展示结论、适用动作、样本数、状态、采用角色和版本。展开后看支持证据、反例及观测局限。

“立即研究”产生一个有预算约束的后台任务；“研究设置”配置模型、周期、范围和预算。没有新样本时显示原因，不制造看似更新的空报告。可查看旧版本以及被废弃的策略。

### 9.2 Agent 中的竞赛与资源

页面首先显示模式及本轮结算状态，再显示榜单：

```text
角色 | 成熟窗口成绩 | 合格/到期样本 | 状态
     | 当前/下一轮份额 | 标准/增强调用比例 | 变化原因
```

分数点击展开浏览、点赞、转发、回复的计数与倍率；关注项显示未接入。资源变化展开原始目标、上限、平滑、借用和预算约束。保护中的角色显示剩余时间，不显示“第末名 0 分”。

全队内部浏览日账与平台请求额度分开展示。已有“额度管理”仍管理请求总上限；竞赛页管理总池内部机会分配。

配置提供四种模式：关闭、只观察计分、调整资源、调整资源和模型。预演先显示预计变化；保存从下一轮生效。紧急恢复共享调度可立即停止竞赛仲裁，保留当前运行任务、预算、冷却和历史数据。

### 9.3 个人页

增加“表现与策略”：显示已采用建议、发帖、成熟时间、结果、实际模型及下一轮实验。用户可以查看、停用某条建议；停用不删除历史，也不修改已经发布的内容。

## 10. 分阶段实施与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A 数据底座 | 发布归属、快照、日账、成熟窗口、只观察榜单 | 不重复计分、不混手工帖、缺失不补零、跨日和转发归属正确 |
| B 策略闭环 | 研究任务、版本简报、采用记录、策略效果页 | 证据引用有效、过期可见、失败不覆盖有效版本、人设与策略分离 |
| C 资源竞争 | 每小时结算、保护期、40/40/20、统一仲裁 | 自动路径不可绕过、份额可行、限流与幂等不受影响 |
| D 模型奖励 | 模型池、连续轮次、预算预留与核销 | 无额外费用越界、不改人格版本、不确定调用不重发 |

部署默认关闭。只观察阶段积累至少两轮数据，确认缺失和归属情况后再启用资源；模型奖励最后开启。

必须覆盖以下验收场景：

1. 点赞 `10→13→9→13→15` 不重复奖励恢复量，取消赞不产生负分。
2. 全队已计 490 次浏览时，同批 12/8 的浏览只再分配 6/4；重放结果一致。
3. 午夜跨日、倍率切换、悉尼夏令时重复小时能分别归档。
4. 发布不足一小时、漏基线、漏端点、字段缺失均有明确状态。
5. 真实采样及时但晚入库可修订；晚采到的快照不能伪造及时端点。
6. 重启、取消任务、重复回执、超过原草稿保留数量均不丢失或重复成绩。
7. 人工帖、旧账号帖、转发对象、已删除帖不能错误转移成绩；删除不抹掉历史分配依据。
8. 新人加入或退出后份额仍合计 100%，约束冲突有原因；空闲借用不改变保障份额。
9. 全零、负分、并列、无可比样本不引发除零、随机奖励或模型来回切换。
10. 待审模式和暂停角色不被竞赛自动启用；新配置不使旧草稿失效。
11. 多进程同时结算只能提交一个有效版本；模拟额度不足、超时和不确定发布仍沿用核对。
12. PostgreSQL 与便携备份恢复后的归属、保护、计分和资源决定一致。

测试使用隔离数据和模拟模型／平台，不以真实发帖验证调度。研究效果和模型升级效果通过后续同预算对照评估，工程测试通过不代表关注度必然提升。

## 11. 设计评审结论

首版优先做到三点：成绩可以追溯到真实观测；建议可以追溯到采用后的成果；资源变化可以解释并回滚。官方权重保持一致，公开数据无法提供的事件与归因明确保留为空。

页面原型中的角色、成绩和资源比例均为设计示例；展示比例用于说明交互，不代表真实账号表现或已经应用的设置。

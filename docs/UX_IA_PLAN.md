## 0. 结论摘要

1. **现在的问题不是功能少，而是分类按"技术模块"而不是按"每天要做的事"**：
   - 顶栏有 9 个平级入口；
   - 「AI 工作流」下面又有 5 个带编号的"步骤"和一个设置链接，把内容策略、Agent 运营和系统配置混在一条假想的流程里；
   - 每天最常用的「Agent 管理」排在第 4 步，「待处理操作」还要再点进一个标签页。
2. **重要设置散在 13 处**。其中 3 个只藏在页面内部，平时看不到：
   - **Agent 生成流程（分段 / 原流程）**，放在「事实库」页的设置里；
   - **"审核连接不可用，相关外发已暂停"**，只在「AI 审核」页显示；
   - **"当前已跳过全部 AI 审核"**，同样只在「AI 审核」页显示。
3. **最深的功能要点 4 到 5 次**：
   - Blue 赛道的账号筛查：AI 工作流 → 分析工作台 → 举报线索 → 本地详细检查，共 4 层；
   - 角色历史回忆：5 层；
   - 竞赛模式设置：4 层。
4. **新结构**：左侧边栏分 5 组，共 20 个入口，任何功能点一次就能到。最常用的放在最上面。
   - 比赛：驾驶舱、积分、规则、Blue 举报
   - Agent 运营：角色、待处理、发布审核、资料筛选、额度与竞赛
   - 内容策略：顾虑雷达与研究、事实库、AI 工作台
   - 数据：帖子、账号、新闻、数据分析
   - 系统：采集与运行、设置中心、AI 连接、API 参考
5. **URL 第一步一律不改**：
   - 侧边栏的高亮和面包屑按"路径 + 查询参数"判断，所以 `/ai/...` 这类旧前缀不会显示在界面上；
   - 现有 7 条重定向全部保留，书签和 81 处站内链接都不会失效。
6. **新增 4 个外壳组件**，都不需要后端：
   - 面包屑；
   - **Ctrl+K 命令面板**：值得做，用来按名称跳到功能、标签页或设置，按 ID 跳到帖子或账号；
   - **设置中心**：全部设置的索引，每项链接到唯一的修改位置，本身不能改设置；
   - 统一的空状态和错误状态"下一步"指引。
7. **和原 C 第二阶段对齐**（D15 后由 E 实施）：
   - 驾驶舱就是 `/`；
   - 采集和覆盖移到 `/operations`，正好落在「系统 › 采集与运行」；
   - 分析页从 8 个标签减到 4 个，旧的 `analysis_tab` 值继续能打开（见第 15.5 节的对照表）。
8. **页面 UI（第二部分）**：
   - 先统一视觉规范：现在全站有 208 种颜色、23 种字号、12 个断点；
   - 统一用词：同一个"AI 连接"现在有 7 种叫法；
   - 再逐页按"先结论、后明细，明细收进高级"重排。
   - 新的列和图表（立场、疑似机器人、门槛、舆论走向）依赖 C 的 P0-1 和 P1-1 接口，见第 18 节。接口没上线时这些列先不显示，不影响其余改动上线。

- **左侧固定侧边栏**，替换现在的顶栏：

## 4. 全局元素

### 4.1 全局状态条（页头，分步 3）
只在异常或需要处理时出现小标签，正常时只有一个灰色"运行正常"。每个标签都能点，点了直接去处理的页面：

| 标签 | 条件 | 点了去哪里 |
|---|---|---|
| Agent 已暂停 | 队伍设置里"持续运行"是关 | 角色 › 队伍设置 |
| 维护中 | `maintenance.active` | 角色 |
| 外发已暂停 | 审核连接不可用 | 发布审核 |
| 已跳过审核 | 审核被设成跳过 | 发布审核 |
| 采集已暂停 / 停滞 | 调度关闭，或采集状态不健康 | 采集与运行 |
| 积分同步异常 | 扩展同步状态不健康 | 采集与运行 |
| 待处理 n | 有未完成操作或未确认通知 | 待处理 |

**数据来源**：
- 现有接口分散在 `/agents`（较重，带草稿和事件）、`/agents/review`、`/operations`（较重）、`/extension-status`。外壳去逐个请求它们不划算。
- 建议后端加一个轻量只读接口 `GET /api/nav/status`：缓存 30 秒，返回上表各项的布尔值和数字，约 30 行。它要改 `server.py`（共享文件），需要协调指派并安排窗口（问题 Q5）。
- 接口上线之前，状态条不做；第 1、2 步不依赖它。

### 4.2 面包屑与页面标题
- 格式：`组 / 页面 / 对象 / 标签`。例如：
  - `Agent 运营 / 角色 / Maya / 操作记录`
  - `数据 / 帖子 / #12345`
  - `内容策略 / 事实库`
- 对象名称：
  - 帖子号取自 `?post=`；
  - 角色名优先读 react-query 里已经缓存的 `/agents` 数据，没有缓存时显示 ID，不额外发请求。
- 标签名：由 `navConfig` 里的标签表按 `?tab` / `?ai_view` / `?analysis_tab` / `?news_view` / `?feed` 查出来。标签表里查不到的值不显示，这样 C、A 改了标签也不会显示错。
- **h1 统一由外壳输出**，取 navConfig 里的页面名。页面内部改用 h2，保证每页只有一个 h1：
  - 第 1 步先只给现在由外壳出 h1 的 5 个页面（帖子、账号、新闻、分析、规则）输出 h1；
  - 自带 h1 的页面（总览、积分、运行、`/ai/*`）先只显示面包屑；
  - 页面所属会话重设计时去掉自己的 h1，再在 navConfig 里打开 `shellTitle`。

### 4.3 Ctrl+K 命令面板：建议做（分步 2）
**为什么值得做**：
- 目的地超过 60 个，包括 20 个入口、约 35 个标签页和 13 个设置项，其中多半藏在标签页或折叠面板里；
- 运营者经常拿着官方日志里的帖子 ID 或账号来查。
- 成本小：前端约 200 行，没有后端改动，不影响任何页面。

**内容**：
- **页面和标签**：全部侧边栏入口，加上每页的标签，例如"事实库 › 待审""采集与运行 › API 日志""角色 › 队伍设置""积分 › 对账"。支持英文别名，如 facts、radar、quota、log、review。
- **设置**：设置中心的 13 项，选中后直接跳到修改位置。
- **对象跳转**：
  - 输入纯数字，出现"打开帖子 #n"（`/posts?post=n`）、"账号 #n"（`/accounts?q=n`）、"作者 n 的帖子"（`/posts?author_id=n`）；
  - 输入文字，出现"在帖子 / 账号 / 新闻中搜索…"；
  - 角色名来自已缓存的 `/agents` 数据。
- **动作**：只放安全的跳转和导出（"导出帖子 CSV"等）。**不放任何会改数据或外发的动作**，比如运行 Agent、执行草稿。
- 入口：Ctrl+K / ⌘K、页头搜索框、404 页。

# 第二部分：页面 UI（D15）

## 11. 分工和原则

**分工**：
- **E**：页面组件和样式、导航外壳、共享展示组件（`common.tsx` 的展示部分，以及新的 `frontend/src/ui/`）。
- **C**：`api.ts` 的数据获取和轮询、性能相关代码、后端接口。E 需要新字段或新接口时发消息给 C，清单见第 18 节。
- **A**：A 的 5 个页面（ContentResearch、ResearchAutomation、FactBank、AIWorkflow、AIReview）等 A 交出后，E 只做视觉统一，不改功能。
- **B**：Agent 页面里的动作选项（允许的动作、手动动作、决策相关的选项）归 B。E 改 Agent 页面的布局时不动这些控件的逻辑，涉及到时先通知 B。

**原则**（每个页面都按这几条检查）：
1. **先结论，后明细**：页面顶部是"现在怎么样"，中间是要处理的事和主内容，明细、原始字段和口径说明放进底部的"高级"折叠。
2. **每个视图最多一个主按钮**（primary），放在页面标题右侧。其余是次要按钮，或者收进"更多"菜单。
3. **常用的放最显眼处**，一年用几次的不占首屏，例如导出、补录、原始 JSON。
4. **每个状态都写下一步**：加载、空、出错、部分数据、被暂停，都要有一句话和一个按钮（第 4.5 节）。
5. **手机宽度能用**：375px 宽时不出现整页横向滚动；主要表格（帖子、账号、待处理操作）改成卡片列表。
6. **日常界面不出现原始 JSON**：排障需要时用"原始记录 ↗"链接，在新窗口打开 `/api/...` 的原始响应。

## 13. 设计规范（U1 落地，后面所有页面都用）

### 13.1 颜色：`frontend/src/ui/tokens.css`，全部用 CSS 变量
| 类别 | 变量 | 用途 |
|---|---|---|
| 品牌 | `--brand` `--brand-weak` | 主按钮、链接、选中态，沿用现在的 `#26705b` |
| 文字 | `--text` `--text-2` `--text-3` | 正文 / 次要 / 辅助，取代十几种灰 |
| 边框和底色 | `--border` `--border-weak` `--bg` `--bg-panel` `--bg-sunken` | 卡片、表头、代码块 |
| 状态 | `--ok` `--warn` `--danger` `--info` `--neutral` | 只用这 5 种。antd 的 Tag、Alert 只用语义名（success / warning / error / processing / default），**不再写 green、orange、red** |
| 立场 | `--stance-yes` `--stance-no` `--stance-undecided` `--stance-unrelated` | 帖子和账号的立场标签。**不用红绿**，因为队伍立场可以设成 Yes 或 No，红绿会暗示"好坏"。另外加一个"我方立场"小标记，跟随队伍设置的 `team_side` |
| 身份 | `--own` `--bot` | "本队"和"疑似机器人"标记 |

`main.tsx` 里 antd 的 `theme.token` 也改成读同一组颜色值，两边保持一致。

### 13.2 字号、间距、圆角、断点
- **字号**只留 6 级：12（辅助）/ 13（表格）/ 14（正文）/ 16（区块标题）/ 20（页面标题）/ 28（指标数字）。
- **间距**：4 / 8 / 12 / 16 / 24 / 32。
- **圆角**：6（控件）/ 10（卡片）。
- **断点**只留 3 个：
  - 手机 `<768`：侧边栏变抽屉，表格变卡片，指标两列；
  - 平板 `768–1199`：侧边栏可以收起；
  - 桌面 `≥1200`。

### 13.4 状态的四种形态
| 形态 | 规则 |
|---|---|
| 首次加载 | 骨架屏的形状和真实布局一致：表格出表格骨架，指标出指标骨架 |
| 刷新 / 翻页 | **保留旧数据**，只显示一个小的"更新中"，不闪成空白。需要 C 在 `useApi` 的列表调用里打开 `retainPrevious`（第 18 节） |
| 长任务 | AI 任务继续用现有的 `AIJobStatus`（已有耗时和取消） |

### 13.5 交互细节
- 站内跳转一律用 `<Link>`（修 V7）；只有下载和 `/docs` 用 `<a href>`。
- 只有图标的按钮必须有 `aria-label` 和 tooltip（例如现在的刷新按钮）。
- 表格里数字右对齐、用等宽数字；时间列统一用 `RelativeTime` 或 `time()`。
- 说明文字收成标题旁边的 ⓘ 提示；同一句话一页只出现一次（修 V10）。

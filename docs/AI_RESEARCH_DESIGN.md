# CTN 数据与 AI 分析方法

核对日期：2026-10-20（Australia/Sydney）。这是一份针对现有数据与当前需求的定向论文阅读，不是系统综述。重点是账号候选筛查、可解释判断，以及让现有帖子、新闻、计数历史参与研究。

## 当前目标：热门规律、完整文章、举报线索

主工作台通过外接聊天 AI 分析高关注文章、直接生成完整文章、审查举报线索。云端向量和重排服务分别配置，本地仅 SQL、BM25、RRF、缓存与证据预算，不安装本地模型。举报任务将行为测量、原帖及关联证据交给 AI，也保留零分与资料不足候选；Jev 仍是单账号结构化复核的可选服务，没有自动举报。

具体公式、阈值、缺失拒判与资格门槛见 [ACCOUNT_SCREENING_METHOD.md](ACCOUNT_SCREENING_METHOD.md)。30/20/20/20/10 是第一版工程权重，**不是以下论文训练或验证得到的权重**。

| 原始研究 | 已阅读的方法要点 | 对本项目的决定与限制 |
| --- | --- | --- |
| [Botometer 101（2022）](https://arxiv.org/abs/2201.01608) | 解释机器人评分、基准和实际使用，指出原始分数不能直接当作真实概率，使用阈值需要结合目标场景。 | 当前分数只排人工检查顺序；不显示“35 分＝35% 是机器人”。Twitter 的模型与阈值不能直接移植到 CTN。 |
| [TwiBot-22（2022）](https://arxiv.org/abs/2206.04564) | 联合账号资料、文本和关系信息，比较不同检测方法与泛化表现。 | 从多类观察取证；现有库没有完整关注图、官方来源标签，不能声称实现论文的图模型，也不能套用论文准确率。 |
| [Social Fingerprinting（2017）](https://arxiv.org/abs/1703.04482) | 用原创、回复、转发等行为序列比较账号群体，寻找共同模式。 | 优先关注跨账号重复与同步，而不只看单条文风。当前实现是完整长文精确匹配与时间窗，不是论文的完整序列检测算法。 |

CTN 中 NPC 也使用 AI，单纯“像大模型写的”不构成区分参赛队账号和 NPC 的方法。账号 ID、立场、缺少新闻报道也不作为评分特征。模型复核分别给出资料充分度、非真实活动证据强度、协同活动证据，不将多项未经校准的输出相加成“举报成功率”。

## 其他分析：数据库负责统计，模型负责解释

现有数据包括帖子正文/版本、公开账号资料、榜单观测、互动快照、回复/转发链接、新闻正文，以及独立的官方积分流水。这些资料的语义不同，不能混为一个文本列表。

| 数据 | 合适的处理 | 当前状态 |
| --- | --- | --- |
| 全范围帖子 | SQL 统计数量、作者数、类型和发布时序。 | 已接入研究上下文，时间线最多最近 48 个非空 UTC 小时桶。 |
| 正文与榜单 | 同类型热门与对照样本；统计范围与引用范围分开。 | 默认100帖候选，可选40/100/200；候选文本检查最多最近5000帖，范围全量计数另列。最终来源按默认8000估算token预算选取，短帖优先保留完整。 |
| 互动快照 | 在实际观测间隔上计算增量，保留缺失和下降。 | 对最多 40 篇选中帖子读取最近两次有效快照，热门/对照交错选取；不把不同间隔当同龄增长。 |
| 回复/转发 | 使用已记录关系补上下文与传播结构。 | 研究上下文包含选帖关系和当前范围已知直接回复数；这不是完整传播网络。 |
| 新闻 | 检索相关报道、区分全文/标题/片段并保留来源。 | 另选最多12条候选，不挤占帖子候选额度；新闻叙事日期与帖子现实时间分开，可使用云端语义召回和重排，最终按证据预算减少。 |
| 官方流水 | 对账与已知结算结果。 | 独立于内容推断；不把点赞等公开计数乘权重冒充实得积分。 |

## 检索与解释的论文依据

| 原始研究 | 方法与适用方式 | 当前边界 |
| --- | --- | --- |
| [RAG（2020）](https://arxiv.org/abs/2005.11401)、[Re2G（2022）](https://arxiv.org/abs/2207.06300) | 检索外部资料后生成；Re2G 合并不同检索来源并重排。适合精确人名、数字、标签与同义表达结合召回。 | 已支持BM25、注入式云端向量、RRF与可选云端重排；无配置时明确使用词项检索。索引只覆盖授权代表候选，尚非全库语义索引。 |
| [GraphRAG（2024；阅读 v2）](https://arxiv.org/abs/2404.16130) | 将局部找证据与全局主题问题区分；对实体关系分社区、形成摘要，再汇总。 | 当前只提供 SQL 全范围汇总与真实回复关系，没有模型抽取的实体图或全库分层语义摘要。真实回复图与实体知识图不是同一种图。 |
| [Lost in the Middle（2023）](https://arxiv.org/abs/2307.03172) | 长上下文中的材料位置与无关信息会影响使用效果。 | 控制上下文预算，压缩冗余元数据并保留来源；不能因为 200 帖更多，就认为结论一定更准。应在实际所用模型上验证。 |
| [ALCE（2023）](https://arxiv.org/abs/2305.14627) | 区分引用是否支持结论、引用是否相关，讨论片段与按需展开。 | 当前检查来源 ID 是否来自本次证据；尚未自动验证每条结论被引文支持。来源存在不等于语义支持。 |
| [FLARE（2023）](https://arxiv.org/abs/2305.06983) | 按生成中的信息需求再检索，补证据后生成。 | 后续可按“待支持的结论”补查；当前没有实现原论文的 token 概率触发器。 |
| [BERTopic（2022）](https://arxiv.org/abs/2203.05794) | 文档嵌入、聚类与 c-TF-IDF 主题表示，并能按时间重估表示。 | 后续适合主题雷达和话题变化；当前没有安装或运行 BERTopic，不把词频表称作语义主题。 |
| [FEVER（2018）](https://arxiv.org/abs/1803.05355) | 找文档、选证据句，再区分支持、反驳与证据不足。 | 用于理解证据核查方法；用户当前不需要独立新闻真假模块，因此前台不增加此任务。内容真假与账号来源分开。 |
| [SEISMIC（2015）](https://arxiv.org/abs/1506.02594) | 以逐次转发时间及转发者度数建模传播。 | 目前只有不完整关系和累计计数快照，不能直接复现或声称可靠预测最终热度；先使用实际窗口增量与覆盖率。 |

上述阅读涉及相关正文方法段；论文实验结果属于原数据、模型与任务，未将其数值准确率当作 CTN 验证。


## 云端检索与有限上下文的实施选择

采用分阶段取材：先算全范围统计，再选热门/普通可比样本或行为候选，再混合检索与云端重排，最后装配任务证据包。热门共性不能由相似度top-K代替总体统计；举报中的跨账号重复事件不作正文去重删除。短帖整篇优先，长文取连贯原句并标字符偏移。返回来源与实际发送来源一致，未发送ID不得通过引用检查。

[HYRR（2022预印本）](https://arxiv.org/abs/2212.10528)为混合检索与重排提供方法背景；[RECOMP（ICLR2024）](https://arxiv.org/abs/2310.04408)支持检索后按任务挑选信息，但过度压缩可能损失证据；[Lost in the Middle（TACL2024）](https://aclanthology.org/2024.tacl-1.9/)研究材料位置与无关内容的影响，不能证明固定8000token最优。[Azure的混合检索说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview)采用词项/向量合并与RRF，可作为行业工程参考，不能套用其效果数值。

协调复核参考[Pacheco等（ICWSM2021）](https://ojs.aaai.org/index.php/ICWSM/article/view/18075)与[Iannucci等（ICWSM2026）](https://ojs.aaai.org/index.php/ICWSM/article/view/42682)：结合共同对象、文本、时间与关系，回到可核对事件解释。当前是有限测量与原帖复核，没有声称复现完整多层图方法；协调不证明恶意意图或竞争方归属。

8000估算token、候选上限和规则权重是工程起点，应在相同预算下比较词项、混合检索和模型表现。当前协议测试不等于真实模型效果评测；全库语义索引、自动补查和监督校准仍未实现。具体使用见[AI分析](AI_ANALYSIS.md)。

## 可选模型接口

普通兼容模型与 TypeSafe Jev 共用 `ctn-account-evidence-v1` 量表。普通模型只返回合法类别；原生 Jev 可以提供分布与 confidence，二者仍不是本赛事经验概率。接口格式正确不保证判断事实正确。

接口来源：[TypeSafe API](https://docs.typesafe.ai/api)、[confidence 含义](https://docs.typesafe.ai/confidence)、[产品介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。产品介绍的速度、成本和校准宣传是供应商自身评估，不作为本项目的检测性能证据。没有真实配置 Key 时只验证模拟协议，不宣称真实模型已验收。

## 举报规则与评分任务

[官方计分 §3](https://capturethenarrative.com/info/competitions/2026/scoring/#3-reporting-inauthentic-posts-and-accounts) 针对非真实活动，由平台版主裁定。帖子裁定 inauthentic 后首队 25 分、之后合资格队 5 分（还受同目标日折扣）；genuine 会使举报队暂停举报 6 小时，该节未列直接扣分。账号直接举报的门槛还包括官方永久隐藏帖和官方行为数量，本地缺少这些状态时保留未知。

[新闻说明](https://capturethenarrative.com/info/competitions/2026/getting-started/#7-read-the-news-websites) 与 [剧情记者设定](https://capturethenarrative.com/info/competitions/2026/setting/#journalism) 也不能推出“无新闻就是假消息”。当前筛选方法不以此作为机器人特征。

后续验证按账号与时间留出，优先衡量前 K 名有效候选比例、误报与人工检查成本；真实来源标签、平台处理结果分别存储。只有具备可信标签与独立校准集以后，才考虑训练和报告概率。当前尚未完成这一校准。

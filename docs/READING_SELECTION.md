# 公共资料筛选

工作台主导航的“资料筛选”（`/reading-selection`）管理所有角色使用的筛选 AI，并展示各角色最近的筛选与调用记录。

## 运行流程

1. 角色需要进行一次决策时，读取已采集资料中的新增候选。
2. 调用 `ctn_data.reading_selection.select(controller, agent, token, candidates)`。公共模块使用独立的筛选连接，将该角色的人设、兴趣和有依据的个人经历交给筛选 AI。
3. 筛选 AI 返回目录中真实的资料 ID 和选择理由。程序保留原文、来源，并将目标帖子及必要的父帖、根帖一起分配阅读预算。
4. 角色使用自己的决策模型，结合这些资料决定发帖、回复、点赞、关注或不行动。既有审阅模式、操作权限和通知确认规则继续生效。

这里没有新增“资料整理 AI”。目录预览与选择也不等于完成阅读、执行动作或确认通知。手动刷新资料沿用本地阅读流程，不因此调用筛选模型。

## API 设置

筛选连接独立于角色里的“角色运行 AI”，也独立于发文竞赛为决策阶段选择的奖励模型。

- 可选择已启用的文字 AI 连接，也可以在筛选页面展开连接管理，新增专用连接。
- 空 `provider_id` 表示跟随工作台默认连接。首次使用也是这个设置，页面显示实际连接及模型。
- 新建专用连接后，需保存筛选设置才会切换公共模块。已有有效的工作台默认连接时，新建专用连接不会替换它；首次添加连接会按既有连接管理规则成为工作台默认。
- 如果复用一个已有连接，编辑其地址、模型或密钥会影响所有使用该连接的功能。需要完全独立的配置时，请新建专用连接。
- 保存筛选设置不会调用模型，也不会启动角色。连接测试仅在显式点击测试时执行。
- 无有效文字连接或筛选输出无效时，保留有界的备用资料目录，并明确记录回退原因；不伪装为 AI 筛选成功。

## 个性化与缓存

共享的是实现和模型配置。每个角色拥有独立的选读缓存，角色之间不会共享个人记忆或直接复用对方的筛选结果。

缓存核对角色身份、实际经历、候选内容和公共筛选配置。切换筛选连接、修改相关模型设置或改变人设会使旧缓存失效。模型限流导致决策等待时，可以复用仍然有效的选读批次，避免每次重试都重新筛选。

正在进行的筛选若遇到配置变化，会拒绝将旧配置的结果交给后续决策。取消请求和角色任务租约仍由原生成任务管理。

## 管理接口

以下接口沿用工作台登录权限；写入需要现有 CSRF token。

- `GET /api/agents/reading-selection`：公共配置、有效模型、安全的可用性提示、各角色最近结果与近期调用记录。
- `POST /api/agents/reading-selection`：保存配置。请求为 `{"provider_id":"连接 ID 或空字符串","expected_revision":1}`，版本号应来自 GET。

并发编辑时，过期的 `expected_revision` 返回 `409`，避免覆盖另一人的设置。接口不返回 API Key，也不接受角色开关或决策配置字段。

前端页面路由和管理 API 分开；角色在同一服务内调用公共模块，无需额外启动一个服务进程。

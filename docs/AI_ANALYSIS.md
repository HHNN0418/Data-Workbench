# AI 分析与云端检索

入口：AI 工作流 → 内容分析（`/ai/analysis`）。同模块的资料筛选（`/ai/reading`）、Agent 管理（`/ai/agents`）和 AI 设置（`/ai/settings`）串起研究、取材与执行。原有链接保留跳转。

内容研究默认展示已保存报告，支持手动生成和后台自动分析。分析工作台中的三个主任务都直接调用所选外接聊天 AI，无需先预览或复制 Prompt。

- **热门文章分析**：从已观察的热门与普通对照，分析话题、开头、结构和表达，说明反例及覆盖范围。
- **生成文章**：先研究证据，再生成一篇完整标题与正文；默认两次聊天请求，第二轮沿用第一轮证据，不重复塞入整包资料。
- **举报线索**：把本地行为候选、测量值、原帖与关联账号交给 AI 审查。混入规则零分与资料不足账号，要求支持证据、正常解释和缺口，规则分仅决定复核优先级。

## 配置三个云端角色

在“AI 工作流 → AI 设置”中分别保存连接名称、Base URL、模型 ID 与 Key，再在任务的“检索服务”中选择向量化和重排连接。可使用不同服务商。模型 ID 由服务商决定，不自动下载安装模型。

## 自动内容分析

在内容研究的「自动内容分析」中选择文字服务、设置间隔并启用保存。默认关闭；间隔默认 60 分钟，可设 15–1440 分钟。后台任务独立于浏览器页面，设置和运行记录保存在数据库中，服务重启后继续调度。

自动分析使用单独保存的帖子范围、研究重点、样本数和输出上限。页面筛选不会直接修改后台范围；可点击「使用当前页面的帖子范围」再保存。每轮读取本地证据，资料未变化且已有报告仍有效时跳过重复模型调用；报告超过两小时、来源失效或研究设置变化后重新研究。启用后会产生所选 AI 服务的调用费用。

报告生成后保存，可选自动将引用及来源校验合格的报告供发文 Agent 参考；此开关默认关闭。手动生成仍保留独立的参考启用操作。资料筛选原本已随 Agent 阅读自动执行，继续按各角色的兴趣与记忆选择原文；Agent 的启停和执行模式在「Agent 管理」中控制。

页面显示最近检查、最近成功、下一次检查及错误。暂停后不安排新分析，已开始的调用可能完成。失败保留已有报告，后续按已保存的调度继续检查。自动调度接口为 `GET/POST /api/ai/research/automation`，保存需 CSRF 和 `expected_revision` 防止覆盖其他页面的修改。

| 角色 | 协议与端点 | 用途 |
| --- | --- | --- |
| 分析/写作 | `openai_chat`，`/chat/completions` | 热门规律、文章生成、举报证据解释 |
| 向量化 | `openai_embeddings`，`/embeddings` | 多语言和同义表达的语义召回 |
| 重排 | `rerank`，`/rerank` | 对候选证据再排序 |

向量接口使用 `model/input/encoding_format:float`，响应按 `index` 还原；重排使用 `model/query/documents/top_n`，响应为 `results[index,relevance_score]`。这是兼容接口约定，并非任意聊天 API 都支持。可参考服务商的 [向量接口](https://docs.siliconflow.cn/docs/api/embeddings-post) 和 [重排接口](https://docs.siliconflow.cn/docs/api/rerank-post)。Base URL 保留需要的 `/v1` 等前缀，粘贴完整上述端点也可自动归一。

未选择向量化时使用关键词检索；未选择重排时保留检索排序。页面展示实际启用状态，不把关键词模式称为语义检索。配置云端服务后的失败明确报错，不自动付费重试。

本地不运行 embedding、reranker、PyTorch 或其他模型；仅做 SQL、BM25、排名融合、少量向量相似度、缓存和证据预算。向量按模型签名与正文哈希缓存，互动、权限与可见性仍每次从数据库读取，缓存不扩大授权来源范围。

## 数据与上下文

普通任务沿用作者、归属、发布时间筛选；举报任务只沿用时间范围，排除本队和明确私密资料，允许查看关联账号原帖。新闻独立于帖子作者和时间筛选。

SQL 范围计数与模型实际收到的来源分别披露。文本候选最多检查最近 5000 条；云端检索在有界代表候选中进行，不等于全库语义扫描。按类型、发表日和实际观察年龄桶挑选热门/普通对照并分散作者；没有可靠同龄窗口时只能讨论累计观察，不能做因果推断。

混合检索结合 BM25、云端向量、RRF 和可选云端重排。不同来源保留原文、时间与出处；跨账号重复在举报任务中是证据，不因同文删除账号事件。

默认完整证据 JSON 预算估算为 8000 tokens，可用 `CTN_AI_EVIDENCE_TOKENS` 设置 2048–32000。估算包含统计、关系、来源与预算诊断；这是保守启发式，并非服务商 tokenizer。任务指令、会话和输出另留空间。优先保留完整短帖；长文选择连贯原句并保留字符偏移，超过预算的来源明确舍弃。返回的引用资料与实际发送的证据一致。

资料聊天同样支持云端检索；无聊天服务时仅本地检索。当前对话保存在页面内存，切换范围或服务会清空。折叠的本地预览与规则筛查无需云端调用。

## 判断边界

公开互动不是官方 NPC 积分，相关性不代表写法导致关注。NPC 本身可能使用 AI，文风、立场和无相关新闻不能证明账号非真实。新闻是赛内参考资料，应逐条核对主张，标题或片段不代表全文。

账号举报需至少一篇官方永久隐藏帖子和至少100次官方行为；目前没有相应官方计数时标未知。帖子被裁定 genuine 可能导致6小时禁止举报。模型只提出待复核线索，不自动发布或提交举报。规则依据见 [账号筛查方法](ACCOUNT_SCREENING_METHOD.md)。

引用检查只核对 ID 来自本次证据，不能保证每句话都被来源语义支持；应展开原帖复核。AI 没有发帖、执行代码或修改数据库工具。原帖、新闻、历史对话均作为不可信数据处理。

## 密钥与请求

Key 由后端单独保存，Windows 使用当前用户 DPAPI，不进入数据库备份、不回显到网页。编辑时留空保留原 Key；迁移机器或更换系统账号可能需重填。不要把 Key 写进任务、草稿或 URL。

切换选择和本地预览不调用云端。点击云端任务或连接测试会发送请求；启用并保存自动分析后，后台也会按调度调用所选服务。连接测试只发送合成短文本。研究与普通 AI 任务共用两个并发槽；单次请求失败不立即重试，自动分析保留错误并在后续调度检查。

普通聊天支持输出上限参数 `max_tokens/max_completion_tokens`、256–8192 tokens 与可选 `thinking` 开关；向量和重排不发送这些生成参数。TypeSafe Jev 仍可用于折叠的单账号结构化复核，不作为聊天或检索服务。

## 研究与验证

架构参考 [HYRR](https://arxiv.org/abs/2212.10528)、[RECOMP](https://arxiv.org/abs/2310.04408)、[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)，以及 [Azure 混合检索](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview) 的分阶段方法。固定预算、样本量与工程阈值尚未在 CTN 数据上证明最优，不套用论文准确率。补查、全库图摘要和监督检测模型尚未实现。

本轮验证使用临时数据库和模拟云端响应，覆盖接口契约、权限、缓存、证据预算和任务流程。没有代填云端 Key，也没有声称完成真实服务商联通或效果验收。

# 工作台登录

工作台接受本地配置的成员账号，所有成员具有相同的工作台权限。成员清单保存在 Git 忽略的 `data/secrets/dashboard_users.json`。迁移已有部署时，请通过受控方式复制此文件。

首次初始化时，在项目根目录运行 `python -m scripts.configure_dashboard_login`，按提示输入成员邮箱、显示名称和密码。每次运行可以添加一名成员，也可以更新现有成员的密码。重启服务以加载更新。邮箱忽略首尾空格和大小写，密码精确匹配。

打开工作台后输入邮箱和密码；登录后右上角显示姓名并可退出。刷新保留当前登录，直接打开分析等页面会在登录后回到原地址。Cookie 最长有效 30 天，正常访问时自动滑动续期（服务端最多每小时更新一次到期时间），关闭浏览器、后端或电脑重启后可恢复。主动退出、连续 30 天未使用或账号密码配置变化后需要重新登录。退出会撤销对应会话并清空浏览器内存中的查询缓存。

认证实现位于 `ctn_data/auth.py`，仅保存加盐 scrypt 密码校验值；会话使用独立 SQLite 文件和 HttpOnly、SameSite=Strict Cookie，HTTPS 接入额外使用 Secure。会话文件只记录令牌的 SHA-256 摘要，不保存 Cookie 原文。SQLite 部署使用数据文件旁的 `<数据库文件名>.sessions.sqlite3`，PostgreSQL 部署使用本机 `data/auth/dashboard_sessions_<连接目标摘要>.sqlite3`，按数据库和用户隔离且文件名不含连接密码；应保留此文件以便重启后恢复登录。浏览器不会收到账号名单、密码或密码校验值。连续十次密码错误后，该客户端在当前五分钟窗口内暂时无法登录。

接口返回 401 时，前端会先重新确认会话；只有确认会话失效才退出。会话确认遇到网络错误时保留当前页面，后续请求可再次确认。

旧版登录状态只存在内存中，首次更新到持久会话版本后需要登录一次；之后的正常服务重启可恢复登录。

工作台数据、导出、备份和 API 文档需要会话。现有 `/api/health`、`/api/bootstrap` 保持可用，供本地启动器检查服务；bootstrap 返回的操作令牌不代替登录。所有写入接口仍检查操作令牌和同源请求。已经绑定的 Chrome 扩展和持有 worker 令牌的 Docker 采集器只在原授权路由使用原认证方式，退出工作台不会暂停后台采集。

本次没有修改数据库表或采集调度，不涉及赛事平台的登录凭据；服务继续使用已有本机访问方式。

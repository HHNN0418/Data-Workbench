# CTN 工作台使用说明

CTN 工作台是 Agent Zero 队伍的本地作战系统：采集赛事平台的公开数据，分析舆论，再让托管的角色 Agent 用各自的赛事账号发帖、回复，最后对照官方得分看效果。

这份说明面向日常使用的成员，按「怎么打开 → 每天看什么 → 每个页面做什么 → 账号与备份 → 出问题怎么办」的顺序写。开发和部署细节见文末列出的文档。

---

## 1. 打开与关闭

### 1.1 本机访问

- 地址：<http://127.0.0.1:8765/>
- 系统由 Windows 计划任务 `CTN-AutoStart` 托管。Windows 登录后会自动启动 Docker、PostgreSQL 和后端。关闭浏览器、关闭 Claude/Codex 都不会停止后端。
- 后端意外退出时，守护进程会在下一轮检查时重启它；守护进程本身退出后，计划任务每分钟拉起一次。
- 注销或关机期间系统不运行，下次登录 Windows 后自动恢复。只开机、停在登录界面时不会启动。

手动打开（比如桌面快捷方式「启动 CTN」失效时），在项目目录的 PowerShell 里运行：

```powershell
.\Launch-CTN.ps1
```

启动器只唤起计划任务，已经在运行时直接打开看板，不会启动第二个后端。

### 1.2 远程访问

- 公网地址：<https://ctn.example.com>，经 Cloudflare Tunnel 转发到本机，登录方式和本机一样。
- 前提：这台电脑开机、已登录 Windows、联网。电脑休眠或断网时远程打不开。
- 配置和排查见 [CLOUDFLARE.md](CLOUDFLARE.md)。

### 1.3 更新代码后重载

改了代码要让线上生效时，**只用**这个脚本，不要直接杀进程：

```powershell
.\scripts\Reload-CTN.ps1
```

它会先暂停领取新任务，等正在进行的生成、发布、注册任务结束，再换上新后端，最后恢复原来的持续运行和采集设置。等待超时会保留旧服务。

> 多个 Claude 会话同时工作时，重载统一由协调会话执行，规则见 [SESSION_BOARD.md](SESSION_BOARD.md)。

### 1.4 日志在哪

| 日志 | 位置 |
| --- | --- |
| 守护进程 | `data/logs/watcher.log` |
| 每次启动的后端 | `data/logs/backend-*.log` |
| 远程桥接 | `data/logs/tunnel-watch.log`、`tunnel-bridge.log` |

## 2. 登录

- 工作台需要使用本地配置的成员邮箱登录。账号规则见 [LOGIN.md](LOGIN.md)。
- 登录保持 30 天，使用期间自动续期；关浏览器、重启后端或重启电脑后不用重新登录。
- 连续输错 10 次密码，该客户端会被锁 5 分钟。远程访问的所有人共用这个失败额度。
- 右上角显示姓名，可以退出。退出只结束你的会话，**不会**停止后台采集和 Agent。

## 4. 每天怎么用

建议按这个顺序过一遍，10 分钟左右：

1. **全链路总览**：先看顶部四个数字（官方得分、Poll 速度、距门槛、落后榜首）。下面如果有红色或橙色的「瓶颈在 X」提示，点进去处理。
2. **采集运行**：确认「统一调度」是自动运行，最近 5 分钟有请求，没有大量 429。
3. **角色**：看有没有角色显示「已封禁」、风险标签或报错；看「未完成操作」里有多少条「待核对」。
4. **待处理**：处理需要人确认的通知和操作（见 5.6）。
5. **风险评估**：看我方账号最近有没有被隐藏的帖子。接近封号的角色要考虑暂停。
6. **得分与目标**：确认积分同步正常，必要时手动登记官方总分。
7. 有空再看分析类页面（顾虑雷达、舆论与洞察、效果归因），调整策略。

## 5. 各页面详解

### 5.1 全链路总览（首页）

- **全链路** 标签：从采集到得分，每一步一张卡片，颜色表示状态（正常/注意/异常/读取失败）。最差的一步会单独提示「瓶颈在 X」，并列出原因和跳转链接。卡片之间的箭头写着流量。
- 顶部数字：
  - 官方得分：最近一次积分快照；快照太旧时会提示。
  - Poll 速度：最近 6 小时和 12 小时的每小时得分，和达到下一个 Poll 门槛所需速度对比。
  - 距门槛：还差多少分，以及按当前速度赶不赶得上。
  - 落后榜首：排行榜只在竞赛门户上，需要点「录入榜首分数」手动抄录。这个数**只保存在你自己的浏览器里**，别人看不到。
- **数据总览** 标签：采集规模、覆盖、最新帖子等原来的概览。
- 底部「效果回流到策略」：归因结算进度和当前顾虑雷达的生成时间。

### 5.2 ① 采集

**采集运行**

- 「统一调度」：总开关「自动运行」和 Latest 检查间隔（30–60 秒）。暂停后不再领新任务，已经开始的请求会做完。恢复后从断点继续。
- 「Docker 代理采集」：两个澳洲出口（Gluetun）的状态。三个出口共用同一份赛事额度，切换出口不能绕过冷却。
- 「本队数据同步」：绑定 Chrome 扩展 ID 和赛事队伍 ID（Agent Zero 是 46），见第 8 节。
- 下方有最近调度记录、最近 200 次调用、采集断点、HTTP 状态和完整采集配置。「导出全部 CSV」导出调用记录。
- 采集只用匿名的公开 GET，不会登录、发帖、点赞或举报。

**帖子流**

- Latest / Trending / 全部已采集三个标签，可按类型、作者、本队筛选和搜索。
- 点一条帖子打开详情：正文的各个版本、互动曲线（连续快照）、引用和回复关系。
- 「导出全部帖子 CSV」导出全部帖子，不截断。

**账号**

- 采集到的所有平台账号：公开资料、归属、已采集帖子数、最近采集时间。我方账号旁有风险标签。
- 「登记本队账号」：填账号 ID、队伍名称和可核验的依据，只保存在本地。没有依据的账号保持「归属未知」。
- 「导出 CSV」导出这张账号表（**公开资料，不含密码**）。要导出我方账号和密码，看第 6 节。

**新闻与话题**

- 新闻文章（目录和全文）、新闻账号（`DailyKingstonia`、`KingstoniaHerald`）、话题标签（目录和热门榜）。
- 剧情里的发布日期和实际采集时间分开显示。「导出新闻 CSV」可导出。

### 5.3 ② 处理

- **标注**：每条采集进来的帖子会标注立场、顾虑和线程深度。页面显示立场分布、顾虑分布和线程深度，可选统计范围。
- **账号识别**：只读。列出每个活跃账号被判成什么（市民 NPC、机器人、高频号、我方、公众人物）和依据，可按身份筛选或搜索。角色只回复被判为市民的账号，所以这里决定了回复对象。
- **风险评估**：对照平台最新帖子流，找出被隐藏的帖子。分「我方账号」「队友账号」「最近的隐藏和待复核帖子」几块，标出离封号还有多远。同样的风险标签也会出现在角色卡片和账号页。
- **事实提取**：从新闻里提取可以引用的事实，进入事实库（见 5.5）。

### 5.4 ③ 分析

- **舆论与洞察**：趋势、账号对比、窗口增长、相关性、词频、互动关系、数据质量七个标签，以及「深度分析」（热门走势、回复传播树、采样覆盖）。结果缓存 60 秒，点「更新分析」立即重算。可「保存快照」「导出结果 JSON」。
  - 注意：公开互动不能换算成 NPC 积分，热度也不等于实得分；词频、相关性不代表因果。
- **顾虑雷达**：市民在担心什么、哪些顾虑在上升，供策略和写作使用。可按账号范围、作者和时间段分析。
- **账号簇 / 竞品**：按行为把账号聚成组，和我方对照，估算各组从市民那里拿到的互动（下限估计，不是官方分数）。
- **Blue 候选**：疑似不真实账号的举报候选，带可信度、所属簇和原因。每张卡片有「用 Simon 的账号举报」按钮：点了会先弹出确认框，显示帖子、作者、可信度和要提交的完整说明，**只有点「确认提交」才会发出**。每条只能报一次，计入当天上限。
- **AI 工作台**：热门文章分析、直接生成完整文章、资料聊天。需要先在「AI 连接」里配好文字模型。

### 5.5 ④ 策略

- **事实库**：角色写作时可以引用的事实、对应顾虑、来源和有效期。
  - 「事实库设置」：写作流程（分步：决策 → 写作 → 检查，或单步）、新事实审核方式（自动生效或人工审核）、是否从新闻自动提取、提取用哪个模型连接。
  - 人工审核模式下，新事实先进待审列表，可以逐条或一键通过。
  - 还可以编辑「反驳」（某个顾虑下 No 方的论点和我方回应）和「禁止说法」。
- **目标与配比规则**：只读，数值直接来自 Agent 使用的代码常量。
  - 发帖与回复配比，以及最近实际的原创/回复比例。
  - 「只回复市民」的目标规则。
  - 原创帖可以 @ 的公众人物，以及各自优先用于哪类顾虑。
  - 班次（悉尼时间）：每组角色哪些小时在班、每小时每个账号最多几条，橙框是市民活跃高峰。
- **提示词与模板**：只读，查看角色写作用的提示词。
- **资料筛选**：显示每个角色最近一次读了哪些资料、是规则选读（不调用模型）还是模型选读，以及最近的筛选记录。

### 5.6 ⑤ Agent 执行

#### 角色页 `/ai/agents`

顶部是四个数字（角色总数、已连接账号、未完成操作、工作模式）和「持续运行」总开关。

- **持续运行开**：所有已启用的角色按各自节奏自动阅读、决策和发布。
- **持续运行关**：不再领取自动任务，但仍可以手动点「只阅读」「阅读并决策」。

标签页：

| 标签 | 内容 |
| --- | --- |
| 角色 | 每个角色一张卡片 |
| 操作记录 | 草稿和动作：待处理、已完成、已跳过、已放弃，可按角色筛选 |
| 收到的通知 | 别人回复或 @ 我方角色的通知 |
| 运行记录 | 全队最新动态 |
| 额度管理 | 平台请求额度和发文竞赛设置 |
| 队伍设置 | 队伍立场、角色数量上限、团队码、禁止内部互动 |

**角色卡片**上显示：执行方式（自动执行 / 审阅后执行）、账号 ID、是否封禁、风险标签、身份标签、背景、立场、兴趣、空闲检查间隔、允许的动作、上次阅读时间、待处理通知数。按钮：

- **只阅读**：刷新这个角色的阅读和通知，不调用决策模型。
- **阅读并决策**：在后台跑一轮阅读和决策，完成后页面自动刷新。生成中可以「取消本次决策」。
- **编辑角色**：打开编辑面板（见下）。
- **连接账号 / 账号设置**：为角色自动注册赛事账号，或用用户名和密码连接已有账号。
- **核对原账号**：注册结果不确定时出现。用保存的原凭据核对，不会换个用户名重复注册。
- **完整管理**：进入这个角色的独立工作区。

**新建 / 编辑角色**

1. 选「角色决策写作 AI」（留空跟随默认连接）。
2. 可以写一句「角色构想」，选背景生成 AI，点「AI 自动生成角色」（编辑时是「AI 丰富角色背景」）。生成结果只填进表单，点「保存角色」才生效。
3. 也可以手填：姓名、用户名、身份背景、个人立场、表达习惯、兴趣、语言、检查间隔、允许的动作、执行方式。
4. 背景用 Kingstonia 世界里的设定。**不要把团队码或密码写进背景、记忆或提示词。**
5. 账号绑定后用户名不能再改。

**角色工作区** `/ai/agents/<角色ID>`：总览、角色配置、经历记忆、操作记录、手动操作、社交关系、收到的通知、个人日志。

- 「经历记忆」可以查看和修正这个角色读过什么、做过什么。
- 「个人日志」可按类型和关键词筛选，点「导出当前筛选 CSV」导出。
- 「清空记忆」会清空记忆和阅读历史，但先在本地保存恢复副本，账号和人设不变。

**队伍设置**

- 队伍立场：默认 Vote Yes。
- 角色数量上限：1–50。
- 禁止 Agent 内部互动：默认开。开着时，我方角色之间不能互相回复、点赞、关注、转发或 @。
- 团队码：保存后用于注册新账号。已保存时输入框留空即保留原值。

#### 待处理

两类事情需要人来处理：

1. **未完成的操作**（操作记录 → 待处理）
   - 审阅模式的草稿：核对来源、理由和目标，改正文后「发布」，或「放弃操作」。正文最多 500 字符。
   - **待核对**：网络中断等原因导致不知道动作是否成功。这时该角色会暂停新操作。发帖和回复要填平台上的帖子 ID 核对；点赞、转发通常系统能自己核对。**待核对的动作不会自动重发**，确认没发出去才能放弃。
   - 也可以「排队发布」，等有发布名额时自动发一次。
2. **收到的通知**：显示每条通知的本地进展、关联动作和平台确认状态。可以「确认跳过通知」，或「重新判断通知」让角色再想一次（已放弃的同一动作不会重放）。

#### 流水线监控

选读 → 决策 → 写作 → 检查 → 发布，每一步的数量、成功率、失败原因；还有按小时（悉尼时间）和按角色的统计。Agent 在维护时这里会提示。

#### 发布审核

- 发布前 AI 审核开关，以及审核用哪个模型连接。审核连接不可用时，相关外发会暂停。
- 「只允许英文」和发布语言检查。
- 审核记录和对应的规则依据。

#### 额度

- 平台请求额度：默认跟随官方（发帖、回复、转发全队共用每分钟 3 次；点赞、关注等各自每分钟 30 次）。可设全队每分钟上限，实际取它和官方额度中较小的一个。
- 服务器上次回执、本地估算剩余、近期请求次数、各角色待办。请求次数不等于成功动作数。
- 发文竞赛设置。

### 5.7 ⑥ 效果

- **得分与目标**：本队数据同步状态、官方活动流水（可搜索、按赛道筛选、导出 CSV）、快照区间对账、赛道分项、官方总分历史、导入批次。「登记官方总分」可以手动录入门户上看到的总分。至少要两份不同时间的快照才能做区间对账。
- **效果归因**：每条发布的效果（代理指标），可按顾虑、角度等分组看平均。
- **曝光与说服**：我们的帖子有没有被看到（浏览、Trending），每个官方小时的情况，以及平台故障时段的标记。

### 5.8 ⚙ 系统

- **AI 连接**：添加模型服务（服务类型、配置名称、模型 ID、等级、上游提供商顺序、连接准备超时、思考模式），启用、设为默认，做「连接测试」。密钥加密保存在本机，不会出现在前端或数据库备份里。
- **规则与情景**：规则版本和来源，Red / Blue / Polling 规则，六类可编辑的情景模板。
- **设置中心**：只读索引，每块写明当前状态和唯一的修改位置。哪个角色选的 AI 连接已被删除，这里会提示。
- **维护**：Agent 维护状态、重载记录、最近的维护事件、数据保留与备份。
- **API 参考**：`/docs` 离线接口文档，`/openapi.json` 是机器可读版本。

## 6. 账号与密码

### 6.1 凭据存在哪里

- 每个角色的赛事账号凭据（用户名、密码、账号 ID、会话 token）存在 `data/secrets/agents/<角色ID>.key`。团队码存在同目录的 `team.key`。
- 这些文件用 Windows DPAPI 加密，**只能在这台电脑、这个 Windows 用户下解开**。数据库备份不包含凭据。
- `data/` 整个目录被 git 忽略，不会提交。

### 6.2 导出账号和密码

在项目目录运行：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\export_agent_accounts.py
```

- 输出文件：`data/secrets/account-exports/agent-accounts-<UTC时间>.csv`，Excel 可直接打开。
- 列：`role`（角色名）、`agent_id`、`username`（登录用户名）、`account_id`、`password`、`account_state`、`in_role_list`（是否还在角色列表里）。
- 屏幕上只显示导出了几个账号和文件路径，不显示密码。没有保存密码的账号会单独计数。
- 脚本只读：数据库在只读事务里读取后回滚，不改动任何角色或凭据。

只要账号清单、不要密码（比如发给队友）：

```powershell
.venv\Scripts\python.exe -X utf8 scripts\export_agent_accounts.py --no-passwords
```

指定输出位置：加 `--output 路径.csv`。

**这个 CSV 是明文。** 请注意：

- 不要提交到 git，不要发到聊天、邮件或网盘。
- 需要长期备份时，放进加密的压缩包或密码管理器，然后删掉明文文件。
- 不要把密码写进角色背景、记忆或提示词。

### 6.3 换电脑或换 Windows 用户

DPAPI 加密的 `.key` 文件在别的电脑上解不开。迁移时：

1. 在旧电脑上用 6.2 导出 CSV。
2. 新电脑上部署好 CTN（`.\Setup-CTN.ps1`），在「队伍设置」重新保存团队码。
3. 对每个角色点「连接账号」，用 CSV 里的用户名和密码连接已有账号。**不要重新注册**，否则会多出新账号。

### 6.4 已有的加密备份

- `data/secrets/agent-credential-backups/<时间>/`：角色凭据的加密副本（只能在本机解开）。
- `data/secrets/encrypted-backups/<时间>/`：数据库连接、代理等基础设施凭据的加密副本，恢复方法见 [credential-storage.md](credential-storage.md)。

## 7. 导出、备份与检查

### 7.1 页面上的导出

| 页面 | 按钮 | 内容 |
| --- | --- | --- |
| 帖子流 | 导出全部帖子 CSV | 全部帖子 |
| 账号 | 导出 CSV | 平台账号公开资料 |
| 新闻与话题 | 导出新闻 CSV | 新闻 |
| 得分与目标 | 导出 CSV | 官方活动流水 |
| 采集运行 | 导出全部 CSV | 采集调用记录 |
| 舆论与洞察 | 导出结果 JSON | 当前分析结果 |
| 角色工作区 → 个人日志 | 导出当前筛选 CSV | 该角色日志 |

### 7.2 命令行

先激活 `.venv`。命令行要连 PostgreSQL 时需要数据库连接串；它是加密保存的，不要打印出来。

```text
python -X utf8 -m ctn_data export posts reports/generated/posts.csv
python -X utf8 -m ctn_data export accounts reports/generated/accounts.csv
python -X utf8 -m ctn_data backup --directory backups
python -X utf8 -m ctn_data doctor
```

`export` 支持的表：`posts`、`counters`、`accounts`、`activity`、`api_logs`、`news`、`analysis`。

- `backup` 把 PostgreSQL 的一致性快照导出成一个可携带的 SQLite 文件并逐表校验。备份不含凭据。
- `restore` 只会生成新的 SQLite 文件，不会覆盖现有数据库。
- `doctor` 检查数据库和配置是否正常。
- **不要删除 Docker 数据卷**，生产数据在里面。

## 8. Chrome 扩展（积分同步）

扩展负责自动同步本队总分和活动流水，不采集公开 Feed。

1. 在 Chrome 扩展管理页「加载已解压的扩展程序」，选项目里的 `browser-extension` 文件夹。代码更新后重新加载一次即可。
2. 扩展弹窗点「打开本地连接设置」，在「采集运行 → 本队数据同步」填扩展 ID 和赛事队伍 ID `46`。
3. 在这个 Chrome 里登录赛事门户。之后扩展每 2 分钟在后台读取一次本队页面和 CSV。

状态判断：心跳 90 秒内、最近一次采集已入库且在 5 分钟内，才显示「同步正常」。登录失效时显示等待登录，重新登录门户即可。扩展不保存 Cookie、密码或团队码。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 打不开 `127.0.0.1:8765` | 等一分钟（计划任务每分钟检查一次）；仍不行就运行 `.\Launch-CTN.ps1`，再看 `data/logs/watcher.log` |
| 远程地址打不开、本机正常 | 看 `data/logs/tunnel-watch.log`；确认电脑没休眠，见 [CLOUDFLARE.md](CLOUDFLARE.md) |
| 页面一直转圈或很慢 | Agent 页轮询较重，先关掉多余的 Agent 页标签再试 |
| 角色一直不动 | 检查：队伍「持续运行」开着、角色已启用、执行方式是自动、在班次内、选的 AI 连接还在（设置中心会提示）、没有待核对的动作卡住 |
| 角色卡片显示「待核对」 | 到「操作记录 → 待处理」核对。发帖和回复要填平台帖子 ID。不要直接放弃，除非确认没发出去 |
| 角色显示「已封禁」或高风险 | 到「风险评估」看被隐藏的帖子；考虑暂停该角色 |
| 生成或审核失败 | 到「AI 连接」做连接测试；看「流水线监控 → 一轮为什么失败」 |
| 大量 429 | 是平台限流，系统会自动冷却。不要重启或换出口去绕过，冷却是持久保存的 |
| 积分不同步 | 看「得分与目标」顶部的同步状态；通常是 Chrome 里门户登录过期 |
| 「角色凭据无法读取」 | 后端不是用原来的 Windows 用户运行的，或 `.key` 文件损坏；用导出的用户名和密码重新「连接账号」 |
| 改了代码没生效 | 需要 `.\scripts\Reload-CTN.ps1` 重载；前端改动还要先构建 |

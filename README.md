# CTN 数据工作台

第三岗 Data / Analytics Engineer 的完整本地工具：公开只读采集、PostgreSQL 历史库（保留 SQLite 兼容）、官方积分对账、规则情景计算、分析、八页看板、导出、备份与恢复。

## 启动

CTN 由本机 Windows 计划任务 `CTN-AutoStart` 独立托管，关闭 Codex 或浏览器不会停止后端。Windows 登录后自动启动 Docker、PostgreSQL 和本地服务；后端退出后守护进程会在下一轮检查时重新启动，守护进程退出后由计划任务每分钟恢复。任务没有运行时限，重复触发不会创建第二个守护进程。此任务使用当前 Windows 用户，注销或关机期间不运行，下次登录自动恢复。

首次安装或修复独立启动，运行 `.\Install-Autostart.ps1`，会安装并立即启动任务。也可双击桌面的“启动 CTN”快捷方式打开看板，或运行 `.\Launch-CTN.ps1`；启动器只唤起计划任务，已运行时检查归属并打开看板，不再直接创建后台服务。日志保存在 `data/logs/watcher.log` 和每次启动独立的 `data/logs/backend-*.log`。采集暂停状态和间隔沿用数据库中的设置；`scripts/Reload-CTN.ps1` 同时保留启动时是否禁用自动采集，保存在 `data/no-auto-collect` 标记中。浏览器扩展仍需打开原 Chrome 用户配置。

Windows PowerShell，在项目目录运行：

```powershell
.\Launch-CTN.ps1
```

打开 http://127.0.0.1:8765/ 。本工作区依赖已安装、前端已构建。首次复制到其它机器时先运行 `.\Setup-CTN.ps1`（需要联网安装依赖、Python 3.12+、Node 22.12+ 与 pnpm 11）；可设置 CTN_PYTHON 指定基础 Python。只启动服务不需要联网安装或队伍凭据。

工作台使用本地配置的成员账号登录。首次部署请先配置成员账号。登录保留 30 天，使用期间自动续期，关闭浏览器或后端重启后可恢复；主动退出或连续 30 天未使用时需要重新登录。后台采集独立运行。账号及接口说明见 [docs/LOGIN.md](docs/LOGIN.md)。

以下 CLI 示例连接当前 PostgreSQL（先激活 `.venv`，在当前 PowerShell 会话读取本机连接配置；不要输出该变量）：

```powershell
$env:CTN_DATABASE_URL = (Get-Content data/secrets/postgres_url -Raw).Trim()
```

显式 `--db data/ctn.sqlite3` 仍可只读检查旧库；迁移后生产命令不要再指定旧库。

```text
python -X utf8 -m ctn_data serve --port 8765
```

本地服务只绑定127.0.0.1。其他队员可使用导出数据或在同一服务的受控接入方案完成后访问；本次没有开放公网/局域网端口、创建共享链接或发布代码。

## 架构与开发

服务更新使用 `scripts/Reload-CTN.ps1`，等待已有任务结束后由 Windows 计划任务重新拉起后端，并验证新进程的系统调度归属。运行 `scripts/Test-CTNSupervision.ps1` 可检查当前托管状态；加 `-SimulateWatcherCrash` 会在排空已有任务后模拟守护进程退出，验证计划任务自动恢复并保存验收报告。

React 19 + TypeScript + Vite 8 → FastAPI + Pydantic + Uvicorn → PostgreSQL 17（Docker 持久卷）。前端使用 Ant Design 6、TanStack Query、React Router 和 ECharts；按页面与图表懒加载，同源部署，无外部 CDN。

`frontend/src/pages/` 是页面，`api.ts` 负责查询缓存、取消请求和本地操作，`common.tsx` 是公共展示组件。`ctn_data/server.py` 负责 HTTP，原有采集、积分和分析模块保持独立。OpenAPI 位于 `/openapi.json`，离线接口参考位于 `/docs`。

前端开发运行 `pnpm dev`（frontend 目录），代理 `/api` 到 8765；后端仍用 Start-CTN.ps1。构建运行 `.\Setup-CTN.ps1 -BuildOnly`。Python 精确依赖见 requirements.lock.txt；前端见 pnpm-lock.yaml。

## 数据与页面

| 页面 | 功能 |
| --- | --- |
| 概览 | 实际采集范围、趋势、官方总分、质量与运行指标 |
| 帖子 | 搜索、类型/作者/本队筛选、分页、详情、正文版本、互动曲线与引用关系 |
| 账号 | 公开资料、本队ID清单与归属证据登记；没有证据保持未知 |
| 本队积分 | 官方CSV导入、已解析/未解析流水、总分快照、区间对账 |
| 新闻 | 目录/全文覆盖、搜索、正文；剧情日期与实际采集时间分开 |
| 分析 | 热门排名轨迹、回复传播树、采样覆盖漏斗、原帖联动下钻，以及趋势、账号、增长、相关性与词频 |
| AI 工作流 | 独立模块，统一内容分析、资料筛选、Agent 管理和 AI 设置；支持后台定时内容研究 |
| AI 审核 | 发布前条款 AI 审核开关、固定英文检查、证据与审核记录；入口在 Agent 管理与 AI 设置之间 |
| 运行状态 | 统一调度队列、本队脚本 / Docker 采集状态、日志、分页断点、在线备份 |
| 规则 | 版本/来源、Red/Blue/Polling规则、六类可编辑情景模板 |

后端采集器仅使用匿名公开 GET；可选 Chrome 扩展在已登录本队页面使用现有浏览器会话执行只读 GET。采集模块不会向赛事平台注册、登录、发帖、点赞、关注、举报或删除。角色 Agent 由成员单独配置，可在赛事平台创建或绑定本队账号，按角色设定阅读资料、生成草稿并发布。AI 会在成员主动执行云端任务、连接测试、Agent 执行，或已启用的后台自动分析需要更新报告时向选定的 AI API 发起请求；资料聊天选择 API 时同样会发送检索资料。自动分析初始关闭，需要选择服务并保存启用。登录仅控制本地工作台访问，不向比赛平台提交数据。

新闻页同时提供新闻文章、新闻账号和话题标签。`DailyKingstonia` 与 `KingstoniaHerald` 有独立的公开帖子跟踪，全部标签目录按游标续采，热门标签保存最新一轮榜单、帖子数和观测时间。三类来源共用每 180 秒一次的 `social_context` 任务及现有请求预算；目录完成时间只表示那次分页已到末页。查看页面不会触发平台请求。

角色发帖、回复及 AI 写作可引用已读新闻来源，并按话题选用已采集标签。标签建议最多 8 个，提示自然使用 0–2 个；单纯刷新热门榜不会触发角色决策。新闻站文章可作为引用资料，回复、点赞、转发的目标仍须是具体社交帖子。

Agent 管理的「队伍设置」提供默认开启的「禁止 Agent 内部互动」全局开关。开启时，受管角色之间禁止回复、点赞、关注、转发和正文 `@提及`；暂停角色及历史绑定账号仍受保护。阅读、原创发文和与外部账号互动照常，人工取消内部点赞或关注可用于清理历史关系。目标选择、草稿保存和最终发送共用该策略，手动操作也需遵守；已有待办被拦截后保留原因且不自动重试，关闭开关不会重放。内部通知保留展示并标记「内部互动，已忽略」，不唤醒决策、不计待处理数、不自动确认。已发到平台的请求继续核对结果。

更新已运行服务时使用 `scripts/Reload-CTN.ps1`：先暂停领取新任务，等待已有生成、执行、注册和自动内容分析任务结束并锁住新入口，再加载服务，最后恢复原来的持续运行与采集设置。等待超时会保留旧服务并恢复运行设置。自动内容分析心跳过期时先确认旧任务已退出，再标记中断；页面停止计时，可点击“重新分析”明确发起一次新请求，重启不会直接重发相同资料。生成心跳过期时只释放能够通过任务 ID、占用令牌和进程归属确认的旧角色占用，不改动结果待核对的动作；发送前再次检查任务占用和授权，失效任务不能继续发送。AI 选择了已知但不属于直接互动目标的通知时，保留合法动作并剔除错配通知，原通知继续待处理，调整原因写入审计。

生成进度先在内存合并，由单个后台线程保存；生成心跳和模型租约使用仅包含角色、租约及阶段审计的轻量事务，与业务写入沿用同一锁，避免覆盖取消状态或新任务。短暂数据库争锁只重试幂等的状态保存，不重发模型或平台请求；所有权、令牌或有效租约丢失时仍停止任务。休眠恢复后，仅对本进程中确实存活、身份完全匹配且角色租约有效的任务给予一次心跳恢复窗口。部署健康检查包含 `agent_heartbeat_policy` 与 `ai_connection_setup_policy`，更新后核对这两个版本标记。

额度扣减、用量与冷却也仅保存额度状态，不加载草稿或记忆。AI 服务的高级配置可调整「连接准备超时」：默认 60 秒，可设 5–300 秒。这是本地可调的运维默认值，不是模型服务商的限制；只用于等待完整结果请求的 DNS、TCP、TLS 与请求发送，初始本地进度保存不占该预算。请求发送完成后，模型思考、静默等待与完整内容接收没有应用设定的总时限，可由成员取消。网络准备超时明确显示失败阶段，不自动重发请求。

## 持续采集

Start-CTN.ps1 默认开启内置调度，保留数据库中的暂停状态。Feed、互动和资料三个通道独立执行，任务、租约和断点写入 PostgreSQL；运行页可暂停或设置 Latest 间隔（30–60 秒）。暂停停止领取新任务，已开始的请求完成后退出；恢复后继续断点，过期租约可重新领取。

页面每 15 秒读取本地数据，运行状态每 4 秒刷新；非服务端推送实时流。分析页每 60 秒读取一次分析结果，结果按筛选范围和视图缓存到数据库，有效期为 60 秒；重新进入、刷新网页或重启服务后只复用未过期的结果，过期后的下一次请求自动纳入最新采集数据并重算。点击「更新分析」可强制立即重算，并清除同范围内其他视图的旧缓存；首次查看未缓存的范围或视图仍需计算。分析结果旁显示生成时间。后台采集照常运行，仅打开网页不会触发额外的平台采集。

只启动看板使用 `.\Start-CTN.ps1 -NoAutoCollect`。默认配置见config.example.json。也可用下面的独立 CLI，但启用内置自动采集时不要再同时启动第二个持续采集器。

```text
python -X utf8 -m ctn_data --config config.example.json collect
```

只运行一次或指定周期数：

```text
python -X utf8 -m ctn_data --config config.example.json collect --once
python -X utf8 -m ctn_data --config config.example.json collect --cycles 3
```

Ctrl+C停止。每轮有限请求/时间/等待预算。OS锁防重复采集；异常退出释放锁，下次启动恢复过期running状态。服务器429冷却持久保存，重新运行不会规避冷却。Latest与Trending保存独立来源；回填期间可刷新头部，仍可能漏掉两次采样间出现又删除的帖子。

调度每 10 秒规划互动任务，待执行及已领取队列最多约 200 条、单轮最多补充 100 条，为规划计算预留缓冲；新帖基线、到期复采、历史轮转按 40% / 40% / 20% 分配并可借用空闲名额。counter_recent_share=0.5。首次采样名额的一半优先保留发布后 10 分钟内的新帖基线；具备早期真实基线的帖子，在基线后 30／60／180 分钟到期时优先复采，容差分别为 6／12／36 分钟。到期采样在普通信息流和正文补采之前执行，容差内已有成功快照的窗口不重复抢占优先级；失败退避 5 分钟。新帖、到期复采和历史轮转共用原有请求、时间和采样预算，空队列可借额；不保证所有窗口都能覆盖。

## 官方积分

可手工导入官方 CSV，也可使用下方 Chrome 扩展自动同步本队活动流水与总分；本工具不读取或导出登录 Cookie。

CSV精确字段：When (UTC), Type, Message。重复文件及重叠导出幂等；无稳定事件ID时完全相同的独立事件存在不可消除的去重歧义，报告会说明。

只有明确记载的实得金额进入积分对账。计数、阈值、倍率、贡献次数不会自动乘权重变成实得。当前真实CSV只有5条队伍管理事件，尚无真实计分事件；保留原文及解析原因，后续可扩展解析器。

```text
python -X utf8 -m ctn_data import-activity path/to/activity.csv
python -X utf8 -m ctn_data record-score 0 --source official-team-page --note checked-by-team
```

总分快照应填入官方页面实际显示值。至少两份不同时间的快照才能形成区间对账。快照是本地抄录，不冒充未确认的官方积分API。

## 与队员程序接入

本工具只自动记录自己采集器的调用。其它成员提供脱敏JSONL，每行如：

```json
{"occurred_at":"2026-10-19T07:00:00Z","service":"social","method":"GET","path":"/api/posts","status":200,"duration_ms":120,"retry_count":0}
```

```text
python -X utf8 -m ctn_data import-api-logs team-logs.jsonl
python -X utf8 -m ctn_data team-accounts 123 456 --evidence team-maintained-account-list
```

导入不执行所记录的请求。只读取白名单日志字段，丢弃headers/body/query；错误文本对常见秘密键值脱敏。不要将密钥、口令、token、队伍代码写入任何日志。

可从Python或外部人工分析导入带版本的标签：CSV字段post_id,label,value,source,version。

```text
python -X utf8 -m ctn_data import-labels labels.csv
```

## 分析与导出

```text
python -X utf8 -m ctn_data analyze --window-minutes 60 --output reports/generated/analysis.json
python -X utf8 -m ctn_data export posts reports/generated/posts.csv
python -X utf8 -m ctn_data export counters reports/generated/counters.csv
```

同窗口分析要求发布后早期真实基线和目标附近真实端点，不插值，不补0；缺失时显示排除原因。快照流式按帖读取，明细截断不影响全样本汇总与相关统计。内存仍随帖子、词汇、时间桶、账号关系和单帖最长历史增长。CSV原始表导出无行数截断。

分析结果保留趋势、账号对比、窗口增长、相关性、词频、互动关系、数据质量七个同级标签，在其右侧为「深度分析」。AI 功能已抽离到独立的「AI 工作流」主导航，内部依次为内容分析、资料筛选、Agent 管理和 AI 设置。旧 AI 分析、Agent、资料筛选及配置地址会跳转到对应新入口。深度分析内切换热门走势、回复传播、采样覆盖：排名热力图与轨迹、对话规模散点与分支树、30/60/180 分钟覆盖热力图与漏斗。选帖状态跨视图保留，点击分支聚焦后同步显示层级和回复时间分布；原帖详情在抽屉中展示。口径说明收进图标题旁的信息提示。

AI 分析的三个主任务是热门文章分析、直接生成完整文章、举报线索复核；选择外接文字 AI 后即可执行。向量化与重排分别配置云端服务，本地只做统计、关键词、排名融合、缓存与证据预算，不安装本地推理模型。资料聊天也支持云端混合检索；未配置向量服务时明确使用关键词。支持多个 API，密钥不进入前端响应或数据库备份。配置方法、上下文预算与能力边界见 [docs/AI_ANALYSIS.md](docs/AI_ANALYSIS.md)。

联动条件保存在 URL：`analysis_tab`、`deep_view`、`rank_sort` 控制视图；`focus_post_id` 选帖；`sample_stage` / `sample_status` 筛选采样状态；`sample_batch` 只筛选明细的发布时间桶，不改变范围内汇总。点击覆盖单元同时选择批次和窗口。覆盖率使用已过采样期限的帖子为分母，无早期基线时以最迟允许基线加窗口与容差计算期限；尚未到期不记为漏采。三个对比窗口容差固定为窗口的 20%，原漏斗继续使用当前筛选参数。

排名仅来自 `trending`／`browser_trending` 的真实观测；空档和两端之外的在榜状态未知，观测跨度不作为连续在榜时长。回复树汇总只包含筛选内帖子，筛选外祖先和缺失父帖单独标识，循环关系断边并保留原始关系。漏斗区分等待端点、已错过端点、指标不完整和计数下降；树、轨迹和明细截断均显示总量，汇总不受截断影响。

公开互动不能换算NPC积分；热度不是实得；认证标记不是NPC标签；词频/相关性/引用关系不等于观点改变或因果。没有官方单帖明细时无法精确归因。

## 备份、恢复与检查

```text
python -X utf8 -m ctn_data backup --directory backups
python -X utf8 -m ctn_data --db data/restored.sqlite3 restore backups/ctn-TIMESTAMP.sqlite3
python -X utf8 -m ctn_data doctor
```

PostgreSQL 备份从一致性快照导出为可携带的 SQLite 文件（ctn-pg-*.sqlite3），校验逐表内容、外键和完整性；原生 SQLite 模式使用在线 backup API。restore 命令只创建新的 SQLite 文件，不覆盖现有库；恢复 PostgreSQL 时使用 migrate-postgres 迁入一个空目标库。生产卷保存在 Docker，原 SQLite 和迁移前备份仍保留。

## Chrome 本队数据同步（1.3.2）

源码：`browser-extension/`。安装包：`reports/generated/ctn-browser-extension.zip`。

1. 首次安装：在 Chrome 扩展管理页加载本项目的 `browser-extension` 文件夹。已有安装更新代码后，只需重新加载扩展一次。
2. 首次连接：扩展弹窗点“打开本地连接设置”，在运行页绑定扩展 ID 和赛事队伍 ID（Agent Zero 为 46）。已绑定无需重填，本地服务地址为 `http://127.0.0.1:8765`。
3. 连接后默认自动采集，正常运行时约 30 秒内检查绑定。自动复用本队页面；没有时在后台打开，不关闭现有标签页。无需逐页启动。

Chrome 脚本 1.3.2 仅自动同步本队总分和活动流水，每 2 分钟在后台重新请求队伍页面和 CSV，无需整页刷新。扩展每 30 秒检查是否到期，页面自身定时器作为另一触发入口，同一次定时采集不会重复请求；“立即检查与同步”会要求重新取数，仍遵守登录等待和限流冷却。连接后优先复用本队页面，没有时自动打开。无需 Chrome NordVPN。公开 Feed、帖子互动及关联数据全部由后端与 Docker 采集器处理。登录失效时保留本队页面并显示等待登录，不重复打开页面；不会保存 Cookie、密码或 TEAMCODE 事件。

1.3.2 将连接心跳、成功采集和成功入库分开显示。只有心跳在 90 秒内、最近一次真实采集已经入库且在 5 分钟内，才显示同步正常；等待登录、冷却、缓存不足、待入库和超过 5 分钟未成功各自显示原因。旧记录补传不会把最新总分显示倒退。每次成功回执保存过滤访问码后的 CSV 摘要、有效行数和最新事件时间；事件时间不代表平台何时提供该事件，不能将两者差值直接当作采集延迟。

实现依据 Chrome 官方的 [storage 配额与失败行为](https://developer.chrome.com/docs/extensions/reference/api/storage#property-local) 和 [alarms 调度说明](https://developer.chrome.com/docs/extensions/reference/api/alarms)。后台闹钟也可能被系统延后，电脑休眠时不承诺固定间隔。

1.3.1 修复数据库暂时不可用时误丢缓存的问题：可重试或结果不确定的记录保留原 ID，至少等待 30 秒后重交；明确不可重试的记录才隔离。重载扩展后生效。项目问题修复、性能基准和数据库 v4 升级说明见 [docs/PROJECT_REVIEW_FIXES.md](docs/PROJECT_REVIEW_FIXES.md)。

扩展自动持久缓存并分批入库；本地服务离线保留队列，恢复后重试。缓存按 UTF-8 字节及全部存储占用检查，队列上限 7 MB，并预留控制状态空间。持久化未确认时保留原记录 ID，由原标签页每 30 秒重交并暂停新采集；正常恢复不整页刷新。此时应保留原标签页，主动关页或重载扩展仍可能丢失尚未持久化的当次采样。单次官方 CSV 超过 6 MB 会明确暂停，需分批导入，不承诺任意规模或离线期间全量保留。429/401/403 或结构变化暂停，至少等待 5 分钟并遵守更长的 Retry-After（最多记录 7 天）；本队页面自行退避，不暂停公开采集队列。手动恢复不会清空限流冷却。扩展重载、浏览器重启、采集页关闭后会重新检查；弹窗提供全局暂停和恢复。

运行页显示绑定、扩展版本/心跳、本队页面状态，以及最近总分与流水读取/新增/重复条数。心跳超过 90 秒显示等待扩展；绑定成功本身不代表已采集。活动无变化时新增为零是正常去重，仍记录成功观测和总分快照。浏览器后台节流、电脑休眠、登录过期和限流仍会延迟采集。

本地仅接受已绑定扩展的专用入口，并校验 CSRF。帖子按 post_id 合并，传输重试按记录 ID 幂等；旧内容不覆盖新内容。互动按实际观测时间保存连续快照；浏览器来源独立标记。CSV 没有事件 ID，沿用时间/类型/原文与出现次数去重，不能区分完全相同的独立事件。

进度页显示本地已知帖子互动覆盖率、首次失败、字段不全、15 分钟未更新、缺失引用/作者、回填位置及当前请求数。互动积压 ETA 假设不再新增帖子；历史 Feed 不返回 total，无法提供可靠全量百分比或结束时间。帖子详情展示连续快照、相邻增量及采样间隔；首次样本不推算增长，缺失值不补零，负变化保留。

## PostgreSQL 与双澳洲代理（2026-10-19）

17 张历史表、158827 行已逐表 SHA256 校验迁移，证据见 `reports/generated/postgres-production-migration.json`。`data/postgres-active` 让启动脚本选择 PostgreSQL。公开采集使用本机直连和两个 Gluetun 澳大利亚出口，共享同一后端、任务队列和 PostgreSQL。配置见 `docker/PROXY_SETUP.md`；Chrome 仅复用本队页面同步总分和流水，不采集公开 Feed 或互动。

| 公开任务 | 执行与出口 |
| --- | --- |
| Latest、Trending、历史分页与头部刷新 | 支持 Feed 的健康 Docker worker 优先领取；无可用代理执行器时由后端直连接管同一队列与分页断点 |
| 帖子互动快照 | 直连后端和两个 Docker worker 共同领取同一队列，按帖子租约协调；最近已有真实快照时复用，避免重复请求 |
| 作者资料、关联原帖、回复分页、新闻目录与正文 | 任务逻辑在后端执行，每轮从直连和健康 Gluetun HTTP 代理中轮转选择出口；使用同一个只读采集实现，并非每个出口重复扫一遍 |

辅助任务的代理健康条件是：`data/proxy-enabled` 存在，对应 worker 最近 60 秒有心跳，且最近 HTTP 状态为 200。代理不可用时后续调度选择可用出口；已选中代理的请求失败会记录并延期，不在同一次请求中偷偷改走直连。显式代理也不受系统 `NO_PROXY` 绕过。Feed 执行器失联或远端网络失败时可由直连接管；429 则等待共享冷却。

三个出口不叠加赛事额度：Feed 共用最小 8 秒请求间隔，互动共用最小 0.3 秒间隔和同帖租约；所有出口的同一服务、同一接口冷却共同持久保存。收到 429 或额度耗尽提示后遵守冷却，切换出口不清空冷却。这些间隔是本地调度上限，不代表赛事确认的每 IP 配额，也不证明代理已降低 429。日志区分直连 `social`／`news` 与 `proxy:docker-au-a/b`，代理新闻带 `:news` 后缀。

帖子按平台 ID 去重；正文版本和按时间保存的互动快照独立。相同时间、相同计数重试幂等，相同时间不同计数保留到 counter_conflicts；不同观测时间保留真实快照。Docker worker 的租约校验、结果、分页断点与观测收据在同一数据库事务内提交；丢失响应后重交原观测 ID，不重新抓取来冒充同一次观测。过期分页计划不会推进已经改变的断点。

自动恢复范围是 Windows 用户登录后；尚未验证无人登录的开机运行，也未执行整机重启。不要删除 Docker 数据卷。当前验证记录位于 `reports/generated/`，早期报告中的 SQLite 架构、数量和测试数为当时快照。


## 角色 Agent 管理

入口：主导航 **Agent**，地址 `/agents`。队伍目标默认 **Vote Yes**。

每个角色分别保存身份背景、个人立场、表达习惯、关注话题、语言、AI 服务、阅读记忆与运行节奏。可先使用已有采集资料阅读和生成草稿，再在队伍设置中保存团队码，为角色自动注册赛事账号或绑定已有账号。团队码、密码和会话 token 由后端单独加密保存。

角色按人设、记忆、近期消息及自己的通知决定发帖、回复、转发、点赞或跳过。公开资料复用采集缓存，Home 和通知按角色周期刷新；阅读与有效决策分别去重，模型失败可继续处理。页面可审阅目标、理由、来源及通知，并查看实际互动结果。

对外正文按各角色的日常表达生成，避免破折号、Markdown 排版、模板口吻和重复自我介绍。表达风格问题在草稿提示；平台正文长度、身份、目标与幂等校验仍在执行前检查，不静默改写。

成员可按角色选择自动模式或审阅后执行，以及允许的动作。角色依据人设和当前意图自主选择一个自然动作，不按固定优先级回复或机械轮换动作。新资料可提前唤醒决策，待审动作不阻止继续阅读；没有新增资料时等待检查，不重复调用模型。所有角色共用官方分类额度和服务器冷却，Home 与采集器共用信息流额度；没有额外每日动作上限、角色动作间隔或关系反转冷却。通知只逐条确认本次决定处理的内容。结果不确定的动作保留核对状态，点赞和转发可查询原账号关系核对，不能直接重发。

在 **额度管理** 标签统一查看和调整所有 Agent 的平台请求额度。默认跟随官方，各类动作按需共用对应额度；可设置全队每分钟期望上限，也可恢复跟随官方，实际始终取期望上限与官方额度中较小的值。设置立即参与调度，保留已消耗额度与服务器冷却；不会为每个角色预留固定份额。页面分别展示服务器上次回执、本地可用估算、本程序近期请求次数及各角色待办，不把请求次数当作成功动作数。

角色、记忆、草稿和日志随现有 PostgreSQL/SQLite 数据一起保存；凭据不包含在数据库备份中。详见 [docs/AGENT_CONTROL.md](docs/AGENT_CONTROL.md)。

Agent 已与账号、帖子、互动分析和积分页关联。确认成功的发帖、回复和转发直接进入共用帖子库，并安排现有采集队列补齐互动样本；点赞只记录已确认关系。角色卡片可跳转本人账号、本人帖子、互动增长和分析，后续决策会读到这些帖子的实际采样反馈。分析页每 60 秒读取结果，缓存过期后自动重算，也可按“更新分析”立即重算。官方总分仅显示为全队背景；缺少账号或单帖归因数据时，个人得分保持未知，公开互动不换算官方积分。
